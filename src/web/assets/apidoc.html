1. 시작하기

마참뮤직 리모컨의 HTTP·WebSocket 계약을 한 장에 정리한 문서예요. 화면(portal.js · console.js)이 실제로 쓰는 경로와 같은 것만 적었어요.

주소 규칙

모든 경로는 /music 아래에 있어요. 이건 취향이 아니라 제약이에요 — 리모컨 도메인(MUSICBOT_REMOTE_HOST)에서는 /music/* 와 /healthz 를 뺀 나머지가 전부 404 예요 (src/web/mod.rs 의 host_scope_guard). 운영 패널과 리모컨을 같은 프로세스에서 서빙하면서도 서로의 화면이 새어 나가지 않게 하는 장치예요.

ℹ 기준 주소는 리모컨 공개 URL이에요. 이 문서의 표에 적힌 경로 앞에 그 도메인을 붙이면 실제 주소가 돼요. 운영 패널 도메인으로 /music/* 를 부르면 리모컨 도메인으로 307 리다이렉트돼요.

JSON만 오갑니다

/music/api/* 는 요청·응답 모두 JSON이에요. 예외는 폼으로 받는 POST /music/dev-login 과 POST /music/logout 둘뿐이에요.

2. 인증

인증은 세션 쿠키 하나예요. API 키도, Bearer 토큰도 없어요. Discord OAuth 로 로그인하면 서버가 쿠키를 심어 주고, 그 다음부터는 브라우저가 알아서 붙여 보내요.

항목값설명
쿠키 이름 macham_session HttpOnly · SameSite=Lax · Path=/music. HTTPS 이거나 X-Forwarded-Proto: https 면 Secure 도 붙어요.
CSRF 헤더 X-CSRF-Token 세션마다 다른 토큰. 상태를 바꾸는 요청에만 필요해요.
토큰 받는 곳 window.MACHAM.csrf 페이지 셸이 부트스트랩 JSON 에 심어 줘요. 별도 조회 엔드포인트는 없어요.

로그인 흐름

  • GET /music/oauth/start → Discord 인가 화면으로 넘어가요. ?next= 로 돌아올 내부 경로를 실을 수 있어요.
  • GET /music/oauth/callback → 코드를 토큰으로 바꾸고 세션 쿠키를 심어요.
  • POST /music/logout → 폼 필드 csrf 를 검사하고 세션을 지워요.

next 는 /music/ 로 시작하고 스킴·호스트가 없는 값만 통과해요. //evil.example 같은 값이 통과하면 그대로 오픈 리다이렉트가 되니까요.

어떤 요청에 CSRF 가 필요한가

규칙은 단순해요. GET 은 안 붙이고, POST·PUT 은 전부 붙여요. 헤더가 없거나 값이 다르면 403 이고, 본문은 {"error":"CSRF 검증에 실패했어요."} 예요.

⚠ WebSocket 은 CSRF 헤더를 붙일 수 없어요. 브라우저 WebSocket 생성자가 헤더를 못 넣기 때문이에요. 그래서 /events 는 CSRF 대신 Origin 허용목록으로 막아요. Origin 이 아예 없는 클라이언트(비-브라우저)도 거절돼요.

3. 등급과 권한 규칙

한 요청이 통과하려면 두 관문을 지나요. 등급(내가 이 서버에서 뭐냐)과 권한 규칙(이 서버가 그 동작을 누구에게 열어 뒀냐)이에요.

등급 (AccessTier)

등급되는 것어떻게 되나
owner전부. 관리자 정지도 이 등급만 가능봇 주인으로 등록된 Discord 계정
manager관리 콘솔 · 서버 설정 · 정지 · 신고 처리서버 관리 권한(ADMINISTRATOR / MANAGE_GUILD / 서버 소유자) 또는 관리자 지정 역할
member서버 설정이 열어 준 만큼그 서버의 일반 멤버
viewer읽기 전용. 쓰기는 전부 거절서버에서 나갔거나 추방됐거나, 전체 정지 중

viewer 는 어떤 권한 규칙으로도 열리지 않아요. 규칙이 "모든 멤버" 라도 viewer 는 막혀요.

권한 규칙 (PermissionRule)

동작마다 권한 키가 있고, 서버 관리자가 키별로 아래 다섯 중 하나를 골라 둬요.

값이름통과 조건
guildMember모든 멤버로그인한 서버 멤버면 통과
sameVoiceChannel같은 음성채널봇과 같은 음성채널에 있어야 통과
configuredRole지정 역할그 키에 지정된 역할을 하나라도 가져야 통과
administrator관리자manager 이상만
disabled사용 안 함아무도 통과 못 해요 — 관리자도요.

disabled 를 뺀 나머지 규칙에서는 manager 이상이 항상 우회해요. 지정 역할은 키마다 따로 관리돼요 — 검색 역할을 준 사람이 볼륨까지 만지게 되면 안 되니까요.

쓰이는 권한 키: search · vote · chat · playback · seek · volume · queueEdit · skip · autoplay · bulkEnqueue · suggest.

4. 공통 응답·에러

성공 응답의 모양은 엔드포인트마다 다르지만, 조작 계열은 대개 이래요.

{ "ok": true, ... }

실패는 상태코드와 관계없이 항상 같은 모양이에요. 사람이 읽을 한국어 한 줄이 들어 있어요.

{ "error": "곡을 넘길 권한이 없어요." }
코드언제클라이언트가 할 일
400본문·쿼리 값이 틀렸을 때고쳐서 다시. 재시도해도 그대로예요
401세션 없음/만료/music/login 으로 보내요
403CSRF 실패 · 권한 부족 · 정지 · 멤버 아님 · 미승인 서버메시지를 그대로 보여 줘요. 로그인해도 안 풀려요
404대상이 없거나, 서버가 그 기능을 꺼 뒀을 때없는 것으로 취급해요
409재생 상태가 그새 바뀌었을 때 · 봇이 음성에 없을 때상태를 새로 받고 다시 판단해요
429같은 동작을 너무 빨리 반복했을 때잠깐 쉬었다가. 동작별로 최소 간격이 있어요
503통계처럼 꺼져 있을 수 있는 하위 기능그 화면만 접어요

ID 는 전부 문자열

Discord 의 ID 는 64비트라서 JavaScript 의 Number 로는 정확히 못 담아요. 그래서 모든 u64 ID(길드·유저·메시지·채널)는 JSON 에서 문자열이에요. 경로 파라미터로 보낼 때도 문자열 그대로 보내면 돼요.

ETag 와 304

일부 읽기 엔드포인트는 ETag 를 주고 If-None-Match 를 이해해요. 같으면 본문 없이 304 만 돌려줘서, 폴링을 해도 거의 공짜예요. 지금 적용된 곳은 GET …/public, GET /music/api/changelog, GET …/charts/{chart_id} 예요.

5. 길드 스코프 경로

서버(길드)에 매인 것은 전부 이 모양이에요.

/music/api/guilds/{guild_id}/…

{guild_id} 는 Discord 서버 ID 예요. 이 경로로 들어온 요청은 핸들러 본문에 닿기 전에 다음을 순서대로 통과해요.

  • 세션이 있는가 → 없으면 401
  • (쓰기라면) X-CSRF-Token 이 맞는가 → 틀리면 403
  • 내가 그 서버의 멤버인가 → 아니면 목록을 한 번 새로 받아 보고 그래도 아니면 403
  • 봇이 그 서버에 있는가 → 없으면 403
  • 그 서버가 승인됐는가 → 아니면 403 (봇 주인은 통과)
  • 정지 중인가 → 전체 정지면 등급이 viewer 로 내려가요

길드와 무관한 것은 /music/api/prefs 처럼 guilds/ 없이 놓여 있어요. 화면 배치·테마는 서버가 아니라 사람에게 붙는 값이라서요.

7. 유저 API

7.1 길드와 무관한 것

메서드경로필요 권한설명

11. WebSocket

WS /music/api/guilds/{guild_id}/events

폴링을 없애기 위한 통로예요. 프레임은 전부 {"t": 토픽, "d": 데이터} 한 가지 모양이에요. 어떤 토픽은 데이터를 통째로 실어 보내고, 어떤 토픽은 "다시 받아 가라" 는 신호만 보내요. 후자는 그 탭이 열려 있을 때만 재조회하면 돼요.

ℹ 열 때 Origin 허용목록과 세션을 검사하고, 그 다음 길드 인가를 봐요. 거절되면 4403 으로 닫아요 — 이때는 재접속하지 말아야 해요. viewer 는 끊지 않아요. 읽기 전용이어도 지금 나오는 곡은 보여야 하니까요.
토픽 td 에 뭐가 오나
playback재생 상태 — 일시정지·재생 위치·지금 곡·볼륨·반복·셔플
queue.set대기열 전체 {items, mode, sortedAt}
vote{itemId, like, super, total, myVote?}
skipvote스킵 투표 현황 — 몇 명 중 몇 명이 동의했는지
chat.add · chat.react · chat.delete채팅 한 건의 추가 · 반응 토글 · 삭제
presence듣는 사람 · 보는 사람 목록. 초당 1회로 합쳐서 보내요
settings · library · suspension재조회 신호 (cold 계열)
suggestion.add · suggestion.vote · suggestion.status제안 재조회 신호
audit새 활동 로그 한 줄 {entry}
autoplay자동 재생 설정·기준 곡 재조회 신호
lyrics가사 재조회 신호
notice{message, kind} — 화면에 띄울 토스트
server.restarting봇이 곧 재시작해요. 잠시 뒤 다시 붙으면 돼요

개인화된 payload(내 표·내 보관함 같은 것)는 전체로 뿌리지 않고 그 사람에게만 가요. 그래서 같은 토픽이라도 사람마다 내용이 다를 수 있어요.

12. 예제

화면 코드가 실제로 하는 것과 같은 모양이에요.

읽기 — CSRF 없이

const res = await fetch(`/music/api/guilds/${guildId}/state/hot`, {
  credentials: 'same-origin',   // 쿠키가 실려야 한다
});
if (res.status === 401) location.href = '/music/login';
const hot = await res.json();

쓰기 — CSRF 헤더 필수

const res = await fetch(`/music/api/guilds/${guildId}/control`, {
  method: 'POST',
  credentials: 'same-origin',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-Token': window.MACHAM.csrf,   // 페이지 셸이 심어 준 값
  },
  body: JSON.stringify({ action: 'pause' }),
});
if (!res.ok) {
  const { error } = await res.json();
  alert(error);   // 서버가 주는 한국어 문장을 그대로 보여 준다
}

실시간 — WebSocket

const proto = location.protocol === 'https:' ? 'wss:' : 'ws:';
const ws = new WebSocket(`${proto}//${location.host}/music/api/guilds/${guildId}/events`);
ws.onmessage = (event) => {
  const { t, d } = JSON.parse(event.data);
  if (t === 'playback') paintPlayback(d);
  if (t === 'settings') reloadCold();   // 신호만 오는 토픽
};
ws.onclose = (event) => {
  // 4403 = 서버가 접근을 끊은 것. 다시 붙어도 결과는 같다.
  if (event.code !== 4403) scheduleReconnect();
};

이 문서는 링크를 아는 사람만 들어와요. 진입 버튼이나 메뉴는 일부러 만들지 않았어요. 내용이 실제와 어긋나 보이면 src/web/remote.rs 의 router() 가 언제나 정답이에요.
