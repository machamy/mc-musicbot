# 계획 01 — 시각표를 유일한 진실로

작성: 2026-08-16 · 상태: **계획. 구현 없음.** · 이 묶음의 토대

> "최종적으로는 그냥 어느 환경에서도 같은 위치를 보고 들을 수 있게 하는 걸 하려는 거임"
> "노래봇과 재생 위치 공유하는 거는 따로 두는 게 맞는 듯"

---

## 목표를 한 문장으로

**"지금 무슨 곡이 어디까지 갔나" 를 대답하는 곳이 하나가 된다.
디스코드 봇도, 브라우저도, 나중에 붙을 무엇도 그 하나에게 물어본다.**

지금은 반대다. **디스코드가 실제로 재생 중인 위치가 진실이고, 웹이 그걸 따라 본다.**
봇이 음성에 없을 때만 웹이 자기 시각표를 만든다. 그래서 클라이언트가 하나 늘 때마다
"이 경우엔 위치를 어디서 가져오지?" 를 매번 다시 정해야 한다.

## 실제로 어긋나는 자리 넷

진실이 여럿인 것 자체보다, **그것들이 실제로 갈라지는 지점**이 문제다.

### (가) 일시정지가 `started_utc` 를 안 고친다 — ★ 제일 큼

`apply_pause`(`coordinator.rs:312-322`)는 물리 세션이면 songbird 핸들만 만지고 **바로
돌아온다.** 재개할 때도 아무도 `started_utc` 를 다시 찍지 않는다 —
`remote.rs:5222-5228`·`handlers.rs:1116-1119` 는 `resume` + `apply_pause` + `sync_guild`
뿐이고, `sync_guild`(`:797-806`)는 볼륨·일시정지만 다시 건다.

```
N초 멈췄다 재개하면:
  current_position()      = 진짜 위치           (songbird 가 멈춰 있었으므로 정확)
  schedule().started_utc  = N초만큼 낡음
  브라우저                 = startedUtc 를 우선한다 (core.js:399-408)
                          → N초 앞선 위치를 본다
```

**즉 일시정지를 길게 걸수록 웹이 봇보다 앞서 간다.** 스킵·시크·새 곡이 오기 전까지
안 고쳐진다.

**코드상으로는 확정이다.** `apply_pause`(`coordinator.rs:312-322`)의 물리 갈래는
핸들만 만지고 `:321` 에서 `return` 한다. 반면 **가상 갈래는 바로 아래에서 정확히 그
보정을 한다**(`:330-334`):

```rust
(false, Some(frozen)) => {
    v.started_utc = chrono::Utc::now() - chrono::Duration::from_std(frozen)...;
    v.paused_at = None;
}
```

주석(`:324-325`)까지 이유를 적어 뒀다 — *"풀 때 그 지점을 0초로 삼아 `started_utc` 를
다시 잡는다."* **물리 갈래에만 그게 없다.**

> 남은 것은 **숫자**다. 시험: 봇을 음성에 넣고 재생 → 30초 일시정지 → 재개 → 같은
> 프레임의 `positionSeconds` 와 `startedUtc` 로 계산한 위치를 비교.
> 기대: 30±2초 차이. 차이가 2초 미만이면 어딘가 다른 보정이 있는 것이므로 이 절을 다시 쓴다.

### (나) 가상 갈래는 일시정지를 다시 걸지 않는다

물리 갈래는 `sync_guild` 마다 일시정지를 재확인한다(`coordinator.rs:804`).
가상 갈래는 `reconcile_virtual` 이 곡이 안 바뀌었으면 `Handled` 로 일찍 빠져나가면서
(`:623-630`) `state.is_paused` 와 `v.paused_at` 을 **비교하지 않는다.**

### (나-2) 가상 일시정지가 곡 끝나는 시각을 안 미룬다 — ★ 교차검증이 잡음

이게 (나)보다 크다. `spawn_virtual_timer`(`coordinator.rs:690-728`)는

```rust
let remaining = duration.saturating_sub(start_offset);
tokio::spawn(async move { tokio::time::sleep(remaining).await; ... })
```

**타이머를 걸 때 남은 시간을 고정한다.** 그리고 `apply_pause` 의 가상 갈래
(`:326-337`)는 `paused_at`/`started_utc` 만 만지고 **세대를 올리지 않는다.**
그래서 `:711` 의 세대 검사를 그대로 통과한다.

→ **웹 재생기 모드에서 5분 멈춰 놔도 원래 끝날 시각에 다음 곡으로 넘어간다.**
1단계에서 "일시정지를 비교" 만 넣으면 이건 안 고쳐진다. **타이머를 다시 걸어야 한다.**

### (다) 개발자 세션은 코디네이터를 건너뛴다

`remote.rs:5217-5226` 이 `if !session.is_developer` 로 `apply_pause` 를 감싼다.
DB 의 `is_paused` 는 바뀌고 실제 렌더러는 안 바뀐다.

### (라) 시크 선행(lead)이 물리에만 걸린다 — 그런데 물리도 반쪽이다

`schedule_start_in`(`coordinator.rs:274-281`)에 **가상 갈래가 없다.** 웹 재생기 모드에서
시크하면 조용한 no-op 이 된다.

**그런데 물리 쪽도 진짜로 기다리게 하지는 않는다.** 이 함수는 `started_utc` 를 미래로
옮길 뿐이고 렌더러(ffmpeg·songbird)는 이미 소리를 내고 있다. 브라우저도 안 기다린다 —
`webTargetPosition()`(`portal.js:4711-4717`)이 `Math.max(0, ...)` 로 음수를 0 으로
깎아서 **미래 시각이면 그냥 0초부터 즉시 튼다.**

→ 선행이 하는 일은 "모두가 같은 0점에 합의하게" 까지다. "모두가 그 순간까지 기다렸다
같이 출발" 은 지금 아무 데서도 구현돼 있지 않다. **가상 갈래에 함수를 하나 더 부르는
것으로는 안 된다** — 기다림은 렌더러 쪽 계약이다.

### 그리고 일시정지의 표현이 다섯 개다

| 어디 | 표현 |
|---|---|
| songbird | `PlayMode::Pause` |
| `VirtualSession` | `paused_at: Option<Duration>` — **얼린 위치**이지 bool 이 아니다 |
| DB | `guild_states.is_paused INTEGER` |
| 브라우저 JSON | `isPaused` + 별개의 `stopped` |
| 통계용 | `virtual_playback` (`models.rs:339`) |

## 목표 구조

```
                    ┌──────────────────────────────┐
                    │   시각표 (mc-clock)          │
                    │   무엇이 / 언제 0초였나 /     │
                    │   멈췄으면 어디서             │
                    │   ★ 순수. I/O 0. now 를 받음  │
                    └───────────┬──────────────────┘
                                │ 구독
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
   ┌────────────┐        ┌────────────┐        ┌────────────┐
   │ 디스코드    │        │ 브라우저    │        │ 나중에 붙을 │
   │ (songbird) │        │ (YT/SC)    │        │ 무엇        │
   └────────────┘        └────────────┘        └────────────┘
     렌더러 1              렌더러 2              렌더러 3
```

### 규칙 셋

1. **시각표가 진실이다.** 렌더러는 시각표를 따라간다. 반대로 묻지 않는다.
2. **렌더러는 자기 위치를 보고만 한다.** 시각표와 벌어지면 **렌더러가 맞춘다** —
   브라우저가 이미 그렇게 한다(`WEB_SYNC_GAP = 2`, `portal.js:4624`). 디스코드도
   똑같이 만든다.
3. **시각표는 시간을 인자로 받는다.** `Utc::now()` 를 안에서 부르지 않는다.
   그래야 테스트가 실제 시간을 안 기다리고, 30초 일시정지 시나리오를 1ms 에 검증한다.

### 이게 왜 목표를 달성하나

새 클라이언트를 붙일 때 할 일이 **"시각표를 구독하고, 벌어지면 스스로 맞춘다"** 하나로
줄어든다. "봇이 음성에 있으면 A 에서, 없으면 B 에서" 같은 분기가 사라진다.
디스코드는 그 규칙을 따르는 렌더러 중 하나가 된다.

## `mc-clock` 이 갖는 것

```
Timetable {
    item_id: String,             // 큐 아이템 id. 지금도 String (models.rs:QueueItem)
    zero_at: DateTime<Utc>,      // 이 곡의 0초 지점
    paused_at: Option<Duration>, // Some 이면 정지, 그 값이 곧 위치
    duration: Option<Duration>,  // None = 라이브
    generation: u64,             // 늦게 깨어난 타이머를 거르는 세대
}

impl Timetable {
    fn position_at(&self, now: DateTime<Utc>) -> Duration
    fn ends_at(&self) -> Option<DateTime<Utc>>   // paused 면 None
    fn paused(self, now) -> Self
    fn resumed(self, now) -> Self
    fn seeked(self, to, now) -> Self
}
```

> **타입만으로는 (가) 를 막지 못한다.** 처음에 "`resumed()` 를 타입으로 강제하면 (가) 가
> 컴파일 에러가 된다" 고 적었는데, 교차검증이 반박했고 맞다 — 위 서명은 `paused_at` 만
> `None` 으로 바꾸는 잘못된 구현도 그대로 컴파일된다. 지금 코드도 그 불변식을
> **테스트로만** 지킨다(`coordinator.rs` 의 `resuming_rebases_the_start_to_the_frozen_point`).
>
> 그래서 진짜 안전장치는 다른 것이다: **상태 전이를 이 다섯 함수 밖에서 못 하게 필드를
> 비공개로 두는 것**, 그리고 **`paused()` → `resumed()` 왕복 뒤 위치가 보존된다는 성질
> 테스트**. 타입이 아니라 캡슐화 + 테스트가 장치다.

`item_id` 는 지금과 같이 `String` 으로 둔다. `TrackId` 뉴타입을 만들면 `mc-clock` 이
도메인 타입을 알아야 해서 의존 방향이 꼬인다 — 뉴타입은
[PLAN-03](PLAN-03-DISCORD-OPTIONAL.md) 1단계에서 방·사람 id 와 같이 다룬다.

의존: `chrono`, `serde` 뿐. tokio·rusqlite·songbird·axum **없음.**
([PLAN-02](PLAN-02-CRATE-SPLIT.md) 가 이 제약을 컴파일러에게 맡긴다.)

## 벽 다섯

### 벽 1. 물리 위치가 렌더러 파생이다 — 그리고 그건 의도된 것이었다

`coordinator.rs:288-289` 에 주석이 있다: *"물리 계산은 그대로 둔다. `started_utc` 를
보지 않고 핸들 위치를 쓴다."*

**그 판단은 그때 옳았다.** songbird 핸들이 진짜 소리를 내는 지점이고, 벽시계는
ffmpeg 기동 지연·버퍼링만큼 앞선다. 그래서 **뒤집을 때 그 지연을 어디선가 흡수해야 한다.**

→ `zero_at` 을 "ffmpeg 이 첫 프레임을 낸 시각" 으로 보정하거나, songbird 위치를
**시각표를 고치는 피드백**으로 쓴다(렌더러가 진실이 되는 게 아니라, 진실을 교정하는 신호).
이 선택은 2단계에서 실측으로 정한다.

### 벽 2. `reconcile_virtual` 이 683줄짜리 늪이다

`coordinator.rs:477-683`. 이 안에 DB 설정 읽기(`:483`), 웹 리스너 훅 호출(`:485-488`),
캐시 조회(`:558-563`), **yt-dlp 네트워크 호출**(`:567-573`), DB 쓰기, 감사 로그,
`tokio::spawn` 이 다 들어 있고, **정작 시각표 산술은 3줄이다**(`:632-651`).

→ 그 3줄을 `mc-clock` 으로 빼내는 것이 1단계다. 나머지 680줄은 그대로 둔다.

### 벽 3. 위치와 시각표를 따로 두 번 `await` 한다

`current_position()` 과 `schedule()` 이 별도 호출이고 그 사이에 DB `get_state` 가 낀다
(`remote.rs:2230-2253`, `:4089-4148`, `:5373-5386`). **셋이 서로 다른 순간의 사진이다.**

`/state/hot` 만 의도적으로 `schedule()` 결과를 재사용한다(`:3491`, 주석 `:3489-3490`).
그 주석이 이미 문제를 알고 있었다는 뜻이다.

→ 한 번에 스냅샷 하나를 만들어 내려보낸다.

### 벽 4. 곡이 끝났다고 판정하는 곳이 둘이다

| 갈래 | 누가 | 어디 |
|---|---|---|
| 물리 | songbird `TrackEvent::End` | `coordinator.rs:1260-1307` |
| 가상 | 벽시계 타이머 | `coordinator.rs:690-728` |

둘 다 같은 절차(`advance → ensure_autoplay → sync_guild`)로 이어지는 것은 다행이다.
하지만 판정 기준이 다르므로 **같은 곡이 갈래에 따라 다른 순간에 끝난다.**

→ 시각표의 `ends_at()` 하나로 통일하고, songbird 의 `End` 는 **확인 신호**로 강등한다.
(라이브 곡은 `duration == None` 이라 `ends_at()` 이 없다 — 지금도 타이머를 안 건다,
`coordinator.rs:702-704`.)

### 벽 5. 브라우저 쪽은 이미 거의 맞다 — 건드릴 게 적다

`core.js:357-470` 의 `clock` 은 이미 **클라이언트 유일의 보간기**다. 시계 오차 보정
(`skew`, `:392-393`)도 있다.

> 처음에 "씨앗 모드 둘을 `startedUtc` 하나로 통일한다" 고 적었는데 **틀렸다.**
> 교차검증 지적대로, **정지 중 위치는 `startedUtc` 만으로 표현할 수 없다** — 그래서
> 지금 코드가 `positionSeconds` 로 폴백하는 것이고(`core.js:410-419`), 그건 의도된
> 설계다.
>
> 올바른 해법은 씨앗을 하나로 줄이는 게 아니라 **시각표를 통째로 내려보내는 것**이다.
> `{ zeroAt, pausedAt, duration }` 을 주면 정지 중이든 아니든 클라이언트가 같은 한
> 함수로 계산한다. 씨앗이 하나가 되는 게 아니라 **입력이 하나가 된다.**

고칠 것:
- 서버가 `startedUtc` + `positionSeconds` 두 값 대신 **시각표 하나**를 보낸다
- `webTargetPosition()` 이 `Date.now()` 대신 `clock` 을 쓰게 (`portal.js:4711-4717`)

## 단계

### 0단계 — (가) 를 실측한다 (한 시간)

**아무것도 고치기 전에**, 위 "확인 필요" 시험을 돌린다.
로컬 개발 인스턴스(`MUSICBOT_DEV_LOGIN=1`)로는 봇이 음성에 없으므로 **물리 갈래를 재현할
수 없다.** 운영에 손대지 않고 확인하려면 개발용 디스코드 서버가 하나 필요하다.

| 완료조건 |
|---|
| (가) 가 사실인지 **숫자로** 확정된다. 사실이면 이 계획의 1순위 근거가 되고, 아니면 문서에서 지운다 |

### 1단계 — 시각표를 순수 타입으로 뽑는다 (가상 갈래만)

`Timetable` 을 만들고 가상 갈래를 그 위에 얹는다. **물리 갈래는 안 건드린다.**

> **이 단계는 "동작 변경 0" 이 아니다.** 처음에 그렇게 적었는데 교차검증이 반박했고
> 맞다 — (나)·(나-2) 를 고치는 순간 웹 재생기 모드의 일시정지 동작이 **의도적으로**
> 바뀐다. 지금 안 되던 게 되는 것이므로 좋은 변경이지만, 라벨이 틀리면 완료조건도
> 틀린다.

| 할 일 | 근거·주의 |
|---|---|
| `VirtualSession` 을 `Timetable` 로 대체 | `coordinator.rs:57-78` |
| `Utc::now()` 를 인자로 뺀다 | `:75` 가 안에서 부른다 |
| 필드를 비공개로, 전이는 함수로만 | 위 "타입만으로는 못 막는다" 참조 |
| `next_start_utc` 산술을 옮긴다 | `remote.rs:2722-2732` |
| `reconcile_virtual` 이 `Handled` 로 빠지기 전 일시정지 비교 | 벽 (나) |
| **일시정지/재개/시크 때 종료 타이머를 다시 건다** | 벽 (나-2). 세대를 올려 옛 타이머를 죽인다 |

**완료조건 — 웹 재생기 모드, 곡 길이 180초 기준**

| # | 입력 | 기대 |
|---|---|---|
| 1 | 재생 → 60초 대기 | 위치 60±2초, 곡 전환 0회 |
| 2 | 30초 지점에서 일시정지 → 60초 대기 | 위치 **30±1초 고정**, 곡 전환 0회 |
| 3 | 위 상태에서 재개 → 30초 대기 | 위치 60±2초 |
| 4 | 170초 지점에서 일시정지 → 60초 대기 | **곡 전환 0회** ← 지금은 여기서 넘어간다 |
| 5 | 재개 → 15초 대기 | 곡 전환 **정확히 1회** |
| 6 | 100초 지점으로 시크 | 위치 100±2초, 전환 0회, 80초 뒤 전환 1회 |
| 7 | 스킵 | 전환 정확히 1회 (중복 `advance` 없음) |

- 시각표 단위 테스트가 **벽시계를 안 기다린다** — 위 7개를 `now` 주입으로 재현하고,
  테스트 전체 실행이 100ms 이내
- 물리 재생 경로 diff **0줄** (`git diff` 로 확인)

**반증 시험**: 세대 올리기를 빼면 #4 가 실패해야 한다. 안 실패하면 그 시험이 (나-2) 를
못 잡는 것이다.

> **`schedule_start_in` 가상 갈래 추가는 이 단계에서 빼기로 한다.** 벽 (라) 에 적었듯이
> 물리 쪽도 실제로는 아무도 안 기다리게 만들고 있어서, 가상에 같은 함수를 붙이면
> **같은 반쪽짜리가 하나 더 생길 뿐**이다. "모두가 같은 순간에 출발" 은 렌더러 계약
> 문제라 2단계에서 물리와 같이 다룬다.

### 2단계 — 물리 갈래를 시각표 밑으로 넣는다 (제일 어려움)

벽 1 의 선택을 여기서 실측으로 정한다.

| 할 일 |
|---|
| `play_track` 이 `Timetable` 을 만든다. songbird 핸들은 **렌더러 손잡이**로만 남는다 |
| `current_position` 이 시각표를 본다. `handle.get_info()` 는 **교정 신호**로 강등 |
| 물리 일시정지/재개가 `Timetable::paused/resumed` 를 거친다 → (가) 가 구조적으로 불가능 |
| ffmpeg 기동 지연을 흡수하는 자리를 하나 정한다 (벽 1) |

**ffmpeg 지연 보정 — 어떻게 고를지 먼저 정한다**

두 설계(① `zero_at` 을 첫 PCM 도착 시각으로 보정 ② songbird 위치를 교정 신호로 사용)
중 하나를 **실측으로** 고른다.

| 항목 | 값 |
|---|---|
| 표본 | 서로 다른 곡 20회 재생 |
| 측정 | `play_track` 의 `Utc::now()` 시점과 `handle.get_info().position` 이 처음 0 을 넘는 시점의 차 |
| 판정 | 중앙값 < 300ms 이고 표준편차 < 150ms 면 ① (고정 보정으로 충분). 아니면 ② |

**완료조건**

| # | 시나리오 | 기대 |
|---|---|---|
| 1 | 음성 재생 중 30초 일시정지 → 재개 | `positionSeconds` 와 `startedUtc` 로 계산한 위치의 차 **1초 이내** (지금은 30초) |
| 2 | 스킵 | 곡 id 가 정확히 1회 바뀐다. 재생 세대 +1. 5초 이내 소리 남 |
| 3 | 100초로 시크 | 5초 이내 위치 100±2초. ffmpeg 재기동 1회 |
| 4 | 자연 종료 | 전환 정확히 1회. `advance` 호출 1회 |
| 5 | ffmpeg 을 강제 종료 | 스톨 워치독(`coordinator.rs:1079-1130`)이 **30초 이내 복구 1회** |
| 6 | 라이브 곡 | 타이머 예약 0회, 전환 0회 |

## 교차검증이 찾은 빠진 것 (2026-08-16, gpt-5.6-sol effort=xhigh)

계획을 쓰고 나서 별도 프로세스에 넘겨 검토받았다. 아래는 **받아들여 반영한 것**이다.
반영 위치를 같이 적는다.

| 지적 | 반영 |
|---|---|
| 1단계가 "동작 변경 0" 이 아니다 | 라벨 수정 + 완료조건을 7행 표로 |
| `reconcile_virtual` 에 일시정지 비교만 넣으면 가상 종료 타이머는 그대로다 | **(나-2) 로 승격.** 이게 이 검토의 제일 큰 수확이다 |
| 가상에 `schedule_start_in` 만 붙여도 선행은 안 생긴다 | (라) 다시 씀. 1단계에서 뺐다 |
| 브라우저 씨앗을 `startedUtc` 하나로 못 줄인다 | 벽 5 다시 씀 — 시각표를 통째로 보내는 쪽으로 |
| `resumed()` 를 타입으로 강제할 수 없다 | 해당 문단 철회, 캡슐화+성질테스트로 대체 |
| 단일 스냅샷 대상에서 호출부 4곳이 빠졌다 | 3단계에 7행 표로 명시 |
| `TrackId` 의 소유 크레이트가 없다 | `String` 유지로 결정, 뉴타입은 PLAN-03 으로 |
| 4단계에 완료조건 절이 아예 없었다 | 6행 표 추가 |

### 아직 단계가 없는 것 — 다음 개정에서 다룬다

**개발자 세션 우회.** `remote.rs` 의 `api_control` 이 `if !session.is_developer` 로
`apply_pause` 를 건너뛰고(`:5217-5226`), `api_enqueue` 등 다른 경로도 코디네이터를
안 부른다. (다) 로 문제만 적어 뒀고 **고치는 단계가 없다.** 시각표가 진실이 되면
이 우회는 "진실을 안 거치는 쓰기" 가 되므로 반드시 닫아야 한다.

지금 결론을 못 내리는 이유: 개발자 세션은 로컬 검증용으로 **일부러** 코디네이터를
건너뛰게 만든 것이라(봇 없이 화면만 보려고), 그냥 닫으면 개발 환경이 깨진다.
"시각표는 갱신하되 songbird 는 안 건드린다" 로 가야 할 가능성이 높은데,
그건 2단계에서 시각표와 렌더러가 실제로 갈라진 뒤에야 쓸 수 있다.

→ **2단계 완료 후 이 절을 다시 쓴다.**
