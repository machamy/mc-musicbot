## 4. 배포 스크립트 (완료)

`Remove-Item` 으로 **지우고 나서** 옮기고 있었다. 이동이 끝까지 실패하면 옛 exe 까지
사라져 되돌아갈 곳이 없다. 오류 문구는 `옛 빌드가 그대로예요` 라고 해서 사실과 반대였다.

지우는 대신 `.prev` 로 **옆으로 치워 두고**, 실패하면 제자리로 되돌린다.
교체가 끝난 뒤에만 `.prev` 를 버린다.

## 남은 것 — 손대기 전에 적어 둔 계획

### 1. 역할로 보기

지금 상태:

```
라우트    /admin/preview  → admin_permission_preview  (옛 핸들러: 인원수 세기)
새 핸들러 admin_role_view → 아무 데도 안 붙음
콘솔      /admin/roleview → 404
```

`/admin/roleview` 를 새로 등록하고 `admin_role_view` 를 붙인다.
`/admin/preview` 는 인원수 세기 용도로 **그대로 둔다** — 다른 화면이 쓰고 있다.

### 2. `stopped` 가 안 오는 경우

`stopped` 를 `playback` WS 이벤트에서만 읽는다. 곡 변화 없이 봇만 음성에서 빠지면
그 이벤트가 안 오고, 진입 로드(`/state/hot`)도 `stopped` 를 안 넘긴다.

- `/state/hot` 응답을 받을 때 `voiceConnected` 로 `stopped` 를 같이 동기화한다.
- 길드 감시 루프가 **음성 연결 상태 변화**도 변화로 세게 한다. 지금은 곡·일시정지만 본다.

### 3. `requireVoiceForPlayback`

저장 핸들러와 판정에만 있고 설정 스냅샷·콘솔 UI 에 없다. 읽어올 수가 없으니 켜고 끌 수도 없다.
스냅샷에 싣고 콘솔 `order` 섹션에 토글을 넣는다.

### W1. `ops` 중복

`rows` 에 추가한 줄과 아래 전용 항목이 겹친다. **전용 항목을 남기고 `rows` 쪽을 뺀다** —
전용 쪽이 `rule: owner` 로 실제 규칙을 맞게 적고 있다.

### W4. `guild_refresh_at`

사람 수만큼 무한히 쌓인다. 값을 넣을 때 오래된 항목을 같이 걷어낸다
(`oauth_states` 가 쓰는 방식과 같게).

### W3. README / LICENSE

`LICENSE` 는 AGPLv3 인데 `README` 는 "오픈소스가 아니다" 라고 적혀 있다.
**라이선스 판단은 코드 문제가 아니라 사용자 결정이므로 고치지 않고 보고만 한다.**

### 자동추천 다음곡 — 언제 정해지나 (확인 결과)

**곡이 시작되는 순간** 정해진다. 끝날 때가 아니다.

```
play_track 성공
  └ on_track_started
      ├ 15초 뒤 재시도 카운터 리셋
      ├ resolve_preview   ← 여기서 다음 곡을 고른다 (백그라운드)
      │   └ set_preview(guild_id, ...)
      └ prefetch_next     ← 고른 곡을 미리 받아 둔다
```

그래서 곡이 3분짜리면 **시작 직후 몇 초 안에** 다음 곡이 정해져 있다.
대기열에 사람이 넣은 곡이 있으면 추천은 아예 안 돈다(`should_fill_preview`).
도중에 누가 곡을 넣으면 이미 고른 추천은 폐기된다.

**버그였던 것**: `set_preview` 가 저장만 하고 **아무에게도 안 알렸다.**
그래서 서버는 다음 곡을 알면서도 웹은 새로고침해야 보였다.

두 군데를 고쳤다.

1. `set_preview` 직후 `on_queue_sorted` 훅을 부른다 → `queue.set` 이 다시 나가고
   그 프레임에 `next` 가 실린다.
2. 길드 감시 루프의 변화 서명에 `autoplay_preview` 를 넣었다. 대기열 ID 만 보고 있어서
   **`next` 만 바뀐 경우를 통째로 놓치고 있었다.**
