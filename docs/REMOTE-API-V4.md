# 마참뮤직 v4 — 여러 서버가 쓰는 봇으로

v3까지는 **서버 하나**를 전제로 만들었다. v4의 주제는 그 전제가 깨진 것이다.
전역 설정 하나로 되던 것들이 서버별로 갈라져야 하고, 아무나 초대할 수 있다는 사실을
설계에 반영해야 한다.

이 문서는 **이번에 한 것**과 **아직 안 한 것**을 같이 적는다. 근거로 쓴 실측값과
밟은 함정도 남긴다 — 다음에 같은 자리에서 넘어지지 않으려고.

관련 문서: `REMOTE-UI-V2.md`(화면) · `REMOTE-API-V2.md`(계약) · `REMOTE-API-V3.md`(v3 45항목) ·

## 1. 차트 (§15)

### 1.1 검색은 차트가 아니다

v3은 `ytsearch50:한국 인기곡 최신` 같은 검색으로 차트를 만들었다.
죽은 재생목록 ID를 피하려던 것인데, **검색 결과가 곡이 아니었다.**

실측(2026-08-07):

```
435:17  [최신가요 실시간 인기차트] 2026년 8월 1일 1주차 … KPOP 플레이리스트
746:52  [최신가요 실시간 인기차트] 🏆🍉2026년 8월 7일 1주차 …
 59:53  Bruno Mars, Rihanna … Billboard Top 50 This Week
```

7분이 아니라 **7시간짜리 한 덩어리**다. 50개 담으면 대기열이 몇 시간짜리 모음 영상 50개가 된다.

지금은 `YouTube Music Global Charts` 채널(`UCrKZcyOJVWnJ60zM1XWllNw`)의 자동 생성
재생목록을 쓴다. 그 채널에 **325장**이 있고, 그중 27장을 골라 **전부 yt-dlp로 확인하고** 넣었다.

| 분류 | 장수 | 곡 수 | 길이 중앙값 |
|------|-----|------|-----------|
| 인기 | 6 | 50~100 | 3분 21초 |
| 나라별 | 12 | 98~100 | 3분 30초 |
| 장르 | 8 | 50 | 3분 35초 |

> **차트를 추가할 때 규칙:** 재생목록 ID를 넣기 전에 반드시 yt-dlp로 곡 수와 길이를 본다.
> ID는 죽는다. 실제로 두 장이 죽어서 빈 차트가 나갔었다.

### 1.2 주소 네 가지

| 형태 | 성격 |
|------|------|
| `https://music.youtube.com/playlist?list=…` | 지금 인기·나라별·장르가 전부 이것. 정확하지만 ID가 바뀔 수 있다 |
| `tj:hot` · `tj:top:N` | TJ 공식 차트 API를 직접 긁는다 |
| `ytsearchN:검색어` | 안 죽는다. 노래방 채널처럼 **개별 곡을 올리는 채널**에만 쓸 만하다 |
| `internal:…` | 우리 재생 기록으로 만드는 차트. 외부 호출 없음 |

### 1.3 TJ 노래방 (§15.2c)

```
POST https://www.tjmedia.com/legacy/api/topAndHot100
     chartType=TOP|HOT & strType=N & searchStartDate & searchEndDate
→ resultData.items[] { rank, pro, indexTitle, indexSong }
```

**성공 코드가 `"99"`다.** 흔한 규약과 반대라 0이나 "00"을 성공으로 보면 항상 실패로 읽힌다.

`strType` 매핑은 TJ가 공개하지 않아서 **곡을 직접 보고** 확정했다.

| 값 | 분류 | 확인 근거 |
|---|------|---------|
| 2 | 팝송 | Let It Go / Creep / Don't look back in anger |
| 3 | J-POP | 晩餐歌 / Pretender / ベテルギウス |
| 4 | 발라드 | 삭제(이승기) / 좋니(윤종신) / 말리꽃 |
| 5 | 댄스 | 바다의 왕자 / 애상 / REDRED |
| 6 | 트로트 | 임영웅메들리 / 사랑의 배터리 / 안동역에서 |
| 7 | 인디·어쿠스틱 | 스토커(10CM) / 최유리 / 로이킴 |

`chartType=HOT`은 strType을 무시하고 전체 인기 100곡을 준다.

**트는 것은 원곡(AR)이다.** TJ에게는 순위만 빌린다. 검색어에 `TJ노래방`을 붙이면
반주(MR)가 1순위로 잡혀서 노래봇이 노래방 기기가 된다. 검색어는 `곡명 가수`뿐이고,
제목에 `노래방/Karaoke/カラオケ/Instrumental/MR/반주`가 있으면 걸러 다음 후보를 쓴다.
후보를 5개 훑는 이유는, 1위가 반주일 때 버리고 끝내면 원곡이 있는데도 "못 찾음"으로
기록돼 재시도만 낭비하기 때문이다.

TJ는 재생 주소를 안 주므로 곡번호 → 영상을 `remote_tj_tracks`에 캐시한다.
**못 찾은 것도 기록한다** — 안 그러면 없는 곡을 열 때마다 다시 찾는다(최대 3회).

### 1.4 캐시와 프리페치

| 대상 | 수명 | 이유 |
|------|-----|------|
| 일반 차트 | 6시간 | |
| **노래방** | **30시간** | TJ 순위는 하루 단위로 움직인다. 원곡 찾기가 비싸서 자주 받을 이유가 없다 |

프리페치는 10분마다 **한 장씩만** 한다. 그리고 **한가할 때만** 돈다 —
재생 중이거나 리모컨을 보는 사람이 있으면 건너뛴다. 40장을 한 번에 돌리면
yt-dlp를 몇 분씩 붙들어서 정작 사람이 검색할 때 밀린다.

차트 응답에는 내용 해시를 `ETag`로 붙인다. 브라우저가 같은 해시를 들고 오면 `304`다.
시간 기반 캐시는 같이 걸지 않는다 — 순위가 바뀌었는데 옛 목록을 쓰는 구간이 생긴다.

### 1.5 길이 상한

차트 결과에서 **15분 넘는 항목을 뺀다.** 겪은 것 두 가지: 검색형 인기 차트의 7시간짜리
플레이리스트, TJ 트로트 1위였던 **86분짜리 `임영웅메들리`**.
길이를 모르는 항목은 남긴다 — 모른다고 버리면 멀쩡한 곡까지 사라진다.

## 2. 여러 서버 (§25~27)

### 2.1 서버 승인 (§26)

봇 초대는 Discord 쪽이라 막을 수 없다. 그래서 **쓰는 것을 막는다.**

```
새 서버 → pending → (봇 주인 승인) → approved → 사용 가능
                  → (거절)        → blocked
```

- 명령어 게이트는 **핸들러보다 앞**이다. 뒤에서 막으면 대기열이 바뀌거나 음성에 들어간
  뒤에 거절하게 된다.
- **재초대해도 결정이 안 풀린다.** 안 그러면 kick→invite로 차단이 해제된다.
- 봇 주인은 리모컨 길드 게이트를 통과한다(승인 화면을 봐야 하므로).
- `/music/api/owner/guilds*`는 **길드 인가를 안 태운다** — 대상이 애초에 그 게이트를
  통과 못 하는 서버들이다.

### 2.2 곡 알림 방식 (§25)

기본 **갱신**. 곡마다 새 글을 쌓으면 세 시간 세션 뒤 채널에 카드가 60장 남는다.

- 갱신은 **같은 채널일 때만**. 알림 채널이 바뀌었는데 옛 채널 카드를 고치면
  지금 보는 채널엔 아무것도 안 뜬다.
- 갱신 실패(삭제·권한)면 **새로 보낸다.** 조용히 포기하면 곡이 바뀌어도 아무 일이
  안 일어나 고장으로 보인다.

### 2.3 빈 채널 규칙 (§27)

`그대로 두기`(기본) / `재생만 멈추기` / `나가기` + 유예 5초~1시간.

기본이 "그대로 두기"인 이유: 아직 듣는 사람이 있는데 나가버리는 쪽이 더 놀랍다.

봇 주인은 운영 패널에서 **강제**할 수 있고, 그러면 서버 주인은 못 바꾼다.
- 잠금 여부와 **이유를 값과 함께** 보낸다. 회색 처리만 하면 고장으로 읽힌다.
- 잠긴 값 저장은 **403으로 거절**한다. 조용히 무시하면 화면은 저장된 줄 알다가
  새로고침에서 되돌아간다 — 제일 헷갈리는 실패다.
- 판정은 `app::empty_voice_rule` **한 군데**. 두 벌이면 "설정은 나가기인데 안 나간다"가 난다.

## 3. 이번에 잡은 버그

전부 **재시작으로 메모리 상태가 날아가서** 생긴 같은 병이다.

| 증상 | 진짜 원인 |
|------|---------|
| **배포하자마자 서버 3개가 통째로 잠김** | 승인 게이트(§26)를 켜면서 **기존 서버까지 `pending`** 으로 시작했다. 게이트는 앞으로 초대될 서버용인데 어제까지 쓰던 서버를 막아 버렸다. 아래 참조 |
| 권한이 있는데 "권한이 없어요" | 역할 캐시가 메모리 전용. 재시작 직후 Discord 429가 겹치면 `unwrap_or_default()`가 **"모른다"를 "역할 없음"으로** 바꿔서 지정 역할 권한자가 강등됐다. 진짜 Discord 관리자는 멀쩡해서 무작위처럼 보였다 |
| 일시정지가 "CSRF 검증 실패" | 세션은 DB에서 살아나는데 CSRF 토큰만 새로 만들어졌다. 브라우저의 옛 토큰과 영원히 안 맞는다 |
| 곡 담기 "입력값을 확인해 주세요" | 422. 브라우저 검색이 만든 곡 객체에 `sourceUrl`이 없는데 `TrackRef`는 필수였다. 서버 검색 경로는 멀쩡해서 될 때도 안 될 때도 있었다 |
| 붐따 "맨 뒤로"가 앞으로 (v3) | Rust에서 `None < Some(-1_000_000)` |

**교훈:** 세션·역할처럼 사람마다 다른 상태는 메모리에만 두지 않는다.
그리고 `None`과 `Some(빈 값)`을 절대 같게 다루지 않는다 — "모른다"와 "없다"는 다르다.

### 3.1 승인 게이트 사고 (배포 중 발생)

게이트를 켠 첫 배포에서 **쓰던 서버 3개가 전부 잠겼다.** 명령어도 리모컨도 거절.

고치려고 v17에 `INSERT OR IGNORE ... 'approved'` 를 넣었는데 **그것도 안 들었다.**
이미 깨진 빌드가 한 번 떠서 그 서버들을 `pending` 으로 등록해 둔 뒤였고,
`INSERT OR IGNORE` 는 행이 있으면 조용히 아무 것도 안 한다.

최종 형태는 INSERT 다음에 `UPDATE ... WHERE status = 'pending'` 을 같이 돌린다.
이 마이그레이션이 도는 시점에 DB 에 있는 서버는 전부 게이트보다 먼저 있던 서버이므로
대기 상태도 승인으로 올린다. **`blocked` 는 절대 안 건드린다.**

> **새 게이트를 넣을 때 규칙:** "지금 있는 것들은 어떻게 되나"를 먼저 답한다.
> 기본값이 *거부*인 게이트는 기존 사용자를 전부 잠근다.
> 그리고 마이그레이션이 **이미 한 번 잘못 돈 뒤에도** 고쳐지는지 확인한다 —
> 배포는 되돌릴 수 없고, 그때의 DB 상태가 다음 마이그레이션의 입력이다.

레거시(C# 공용) 테이블(`guild_states`·`guild_metadata`)을 raw SQL 로 참조했다가
**테이블이 없으면 마이그레이션 전체가 실패해 저장소가 안 열리는** 상태를 만들 뻔했다.
지금은 `sqlite_master` 로 존재를 확인하고 있는 것만 훑는다.

## 4. 최단 중단 업데이트 (§24)

**진짜 무중단은 불가능하다.** Discord 음성은 UDP 소켓과 암호화 세션이 프로세스 안에 있고,
봇 하나가 같은 길드에 음성 연결을 둘 들 수 없다. 목표는 **최단 중단**이다.

```
신호(Ctrl+C·Ctrl+Break·창닫기·SIGTERM)
  → 브라우저에 server.restarting  (오류 화면 대신 안내)
  → 서버마다 재생 위치 저장        (음성에서 빠지기 전에!)
  → 음성 이탈
  → 종료 (정리 상한 6초)
다음 기동 → 같은 채널·같은 곡·그 지점부터
```

이어붙이기 조건 두 가지: **첫 곡이 그대로**여야 하고 **6시간 안**이어야 한다.

배포 순서도 바꿨다(`scripts/Deploy-Seamless.ps1`).
전에는 `죽이기 → 복사 → 기동`이라 **복사하는 내내 죽어 있었다**(cloudflared가
`i/o timeout`을 2분 넘게 뱉음). 지금은 `복사 → 해시 대조 → 신호 → 교체 → 기동`이라
멈춤 구간이 "기동"만 남는다.

> PowerShell 5.1은 **BOM 없는 `.ps1`을 ANSI로 읽는다.** 한글이 깨지고 파싱까지 실패한다.
> 배포 스크립트는 BOM 붙여 저장한다.

## 4.5 배포 규칙

**모든 빌드·배포에는 버전 번호와 패치노트가 있어야 한다.**

```powershell
.\scripts\Deploy-Seamless.ps1 -LocalExe .\target\release\mc-musicbot.exe -Version v4.3
```

`-Version` 은 필수고, `docs/CHANGELOG.md` 에 `## <버전>` 항목이 없으면 **배포가 거부된다.**
인앱 패치노트가 그 파일 하나를 그대로 읽으므로, 항목이 없으면 화면에서도 빈칸이 된다.

> `CHANGELOG.md` 는 **사용자가 읽는 문서**다. 배포 명령이나 개발 규칙을 거기 적지 않는다 —
> 그대로 앱 안 패치노트 화면에 나간다. 그런 것은 이 문서에 적는다.

### 6.1 승인 화면
리모컨 프로필 메뉴 → `🛡 서버 승인`. **봇 주인에게만 보인다**(다른 사람은 API가 403이라
메뉴 자체를 안 그린다). 대기 중인 개수가 배지로 붙는다 — 어디에도 안 보이면 영영 방치된다.
`botInGuild`가 false면 `봇이 이미 나간 서버예요`라고 적는다. 승인해도 소용없으니까.

### 6.2 로그인 없이 읽기 전용 (§29)
`/music/guilds/{id}/now` — **리모컨 셸을 재사용하지 않는 독립 페이지**다.
셸을 쓰면 로그인 안 한 사람에게 채팅·멤버 코드까지 내려가고, 언젠가 그중 하나가
데이터를 요구하게 된다. 이 페이지는 곡 하나만 그리고 조작 요소가 아예 없다.

나가는 것: 곡 제목·가수·일시정지 여부·대기열 곡 수·앞 5곡 **제목만**.
안 나가는 것: 신청자 이름, 채팅, 멤버, 투표. 그건 서버 안 사람들 정보다.

서버가 끄면(`publicNowPlaying`) 404. 승인 안 된 서버도 404 —
"꺼짐"과 "없음"을 구분해 주지 않는 것도 의도다.
WebSocket 대신 5초 폴링 + ETag를 쓴다. 로그인 안 한 사람에게 소켓을 열어 주면
그 자체가 붙잡아 둘 자원이 된다.

### 6.3 인앱 패치노트 (§30)
`docs/CHANGELOG.md`를 exe에 `include_str!`로 박아 `/music/api/changelog`로 준다.
**원본이 하나뿐**이라 문서와 화면이 갈라질 수 없다.

마크다운 해석은 클라이언트가 하되 **아주 좁게** 한다. 서버가 HTML을 만들면
이스케이프 실수 하나가 곧장 XSS다. HTML은 통째로 이스케이프하고 제목·목록·표·코드·굵게만
되살린다. `<script>`, `<img onerror>`, 속성 탈출까지 7가지 케이스로 확인했다.

프로필 메뉴 → `📝 패치노트`(버전 번호가 같이 뜬다). 새 빌드로 처음 들어오면 한 번 자동으로
뜬다. **처음 쓰는 사람에게는 안 띄운다** — 첫인상이 변경 목록이면 곤란하다.

### 6.4 더 생각해 볼 것
- 노래방 원곡 해석 정확도: 지금은 제목 필터 + 후보 5개. 라이브/커버가 잡히는 경우가 있다
- 프리페치가 승인된 서버만 도는데, 서버가 많아지면 한 tick 한 장으로는 부족할 수 있다
- `remote_tj_tracks`는 전역 캐시다. 곡번호는 TJ 것이라 서버별로 나눌 이유가 없지만,
  잘못 해석된 곡을 고칠 방법(관리 콘솔에서 재해석)이 아직 없다

## §39 같이보기 (watch party)

한 사람이 켜면 나머지에게 물어보고, **수락한 사람만** 영상으로 바뀐다.
서버가 들고 있는 것은 스위치가 아니라 **명단**이다 — 판이 켜져 있다는 것은
"보는 사람이 하나라도 있다" 와 같은 말이다.

**휘발성이다.** `WebState::watch_parties` 에만 있고 DB 에 안 쓴다(`web_listeners` 와 같은 이유).

### `POST /music/api/guilds/{guild_id}/watch`

```json
{ "on": true }
```

| 경우 | 권한 |
|---|---|
| 판이 없는데 `on:true` (**시작**) | `playback` |
| 판이 있는데 `on:true` (**합류**) | 없음 |
| `on:false` (**나가기**) | 없음 |

합류에 권한을 걸면 `playback` 이 관리자 전용인 서버에서 *초대는 뜨는데 수락하면 403* 이 된다.

500ms 레이트리밋. 응답은 `{ "ok": true, "watch": <아래 모양> }`.

### `watch` 토픽 · `/state/hot` 의 `watch`

```json
{
  "on": true,
  "id": "재사용되지 않는 표",
  "startedBy": "123", "startedByDisplay": "민수",
  "count": 2, "watchers": ["123", "456"]
}
```

꺼져 있으면 `on:false`, `id:null`, `watchers:[]`.

**`id` 를 세는 번호로 두면 안 된다.** 서버가 재시작하면 1 부터 다시 시작하는데, 브라우저
탭에 남아 있던 "이 판은 이미 물어봤다" 가 새로 열린 판의 초대를 삼킨다. 배포마다 벌어진다.

**`/state/hot` 에 싣는 것이 늦게 들어온 사람 안내의 전부다.** 진입·새로고침·재연결이 전부
이 경로를 지나므로 따로 초대 이벤트를 쏘지 않는다.

소켓이 끊기면 `presence_remove` 가 웹 리스너와 같은 규칙(마지막 소켓일 때만)으로 정리한다.
## 웹 직접 받기 (v4.72, PLAN-05)

기본은 꺼짐이다. 봇 주인의 전역 허용과 브라우저의 `직접 받기` 선택이 모두 필요하다.
개인 선택은 해당 브라우저에만 저장하며 계정 설정/서버 청취 인원 상한과는 다르다.

### 전역 설정

`GET /music/api/owner/stream`: 봇 주인만 현재 설정과 전송 상태를 읽는다.
`PUT /music/api/owner/stream`: 봇 주인 세션 + `X-CSRF-Token`, 설정 문서 전체 교체.

```json
{
  "enabled": false, "maxTransfers": 10, "bandwidthKbps": 2000, "prefetch": true,
  "routes": [
    { "source": "origin", "enabled": true },
    { "source": "server", "enabled": true },
    { "source": "embed", "enabled": true }
  ]
}
```

- `maxTransfers`: 1~30, 기본 10. 청취자 수가 아니라 전송 중인 응답 수다.
- `bandwidthKbps`: 128~20,000, 기본 2,000. 십진 kbps이며 모든 길드·Range 요청이 공유한다.
  이 안전 예산에는 0=무제한 규칙을 적용하지 않는다. 저장/읽기 양쪽에서 범위를 제한한다.
- `settings` 테이블의 `remote_web_stream` 키에 저장한다. 레거시 스키마 변경은 없다.
- `routes`: 위에서 아래로 켜진 경로만 시도한다. origin=원본 CDN, server=봇 캐시, embed=외부 임베드.
  중복 source는 첫 항목만 유지하고 누락 source는 꺼짐으로 뒤에 붙인다. 모르는 source는 거부한다.
  `routes` 자체를 생략한 옛 설정은 기본 순서를 받는다. 빈 배열은 모든 경로 꺼짐이다.
- `prefetch`: 기본 true. 현재·다음 곡 동시 준비 여부다. false이면 현재 곡만 받는다.
- GET/PUT 응답에는 `active`, `queued`, `sentBytes`, `blobLimitBytes`가 추가된다.
  `sentBytes`는 속도 제한기에 청구한 본문 바이트이며 네트워크 수신 완료 통계는 아니다.

### 상태 프레임

`playback`, `/state/hot`, `/state/cold`, 기존 `/state`에 같은 `stream` 객체가 있다.
watcher 서명에도 준비 여부/크기를 넣어 다운로드 완료를 곡 변경 없이 알린다.
`current`와 `next`는 현재 곡과 바로 다음 곡(큐 첫 곡 또는 활성 자동추천)이다.

```json
{
  "enabled": true, "maxTransfers": 10, "bandwidthKbps": 2000,
  "blobLimitBytes": 33554432,
  "current": {
    "id": "큐-항목-ID", "ready": true, "sizeBytes": 3770000,
    "streamUrl": "/music/api/guilds/1/stream/큐-항목-ID"
  },
  "next": null
}
```

꺼짐/라이브/곡 없음은 descriptor가 null이다. 캐시 미스는 `ready:false`다.
descriptor의 `durationSeconds`는 서버 시각표의 곡 길이다. 디코딩한 파일과 2초 넘게
다르면 이번 곡은 폴백한다. 구간 제거된 캐시를 원본 시각표로 틀어 무음이 생기는 것을 막는다.
URL은 파일 경로가 아니라 길드의 큐 항목 ID를 받는다. 논리 캐시 키를 내용 해시로 보지 않는다.

상태 객체에는 `routes`와 `prefetch`, descriptor에는 원본 조회용 `sourceUrl`도 포함한다.
서명된 CDN URL 자체를 WS 상태 프레임에 싣지 않는다.

### 원본 주소 조회

`GET /music/api/guilds/{guild_id}/stream/{item_id}/source`는 파일 응답과 같은 인가·현재/다음
허용 목록을 검사한다. 전역 기능과 origin 경로가 모두 켜져 있어야 한다. 추출 뒤에도 다시 검사한다.
응답은 `{ "source": null }` 또는 `{ "source": { "url", "mime", "sizeBytes", "durationSeconds", "expiresAt" } }`다.
크기/만료 시각은 null일 수 있다. `Cache-Control: private, no-store`이며 사용자별 현재/다음 각 1초 제한이다.
추출은 전역 최대 2개, 15초 한도, 곡별 결과 60초 공유(최대 128개)이며 재생 전송 슬롯과는 별개다.
yt-dlp 설정 파일·인증 체인을 사용하지 않는 익명 메타데이터 조회다. 오디오 파일은 서버가 받지 않는다.
서버 쿠키·프로필·HTTP 헤더·전체 추출 JSON을 클라이언트에 반환하지 않는다.
HTTPS의 googlevideo.com/sndcdn.com 하위 도메인과 지원하는 오디오 형식만 허용한다.

클라이언트는 원본의 작은 파일을 `credentials:omit` CORS fetch로 받고, 크기 미상/큰 파일은
native audio로 재생한다. fetch 실패 뒤에는 원본 native audio도 한 번 시도한 뒤 다음 경로로 간다.
native audio는 브라우저의 교차 출처 미디어 정책을 따르며 서버 소유자의 인증을 대신 보내지 않는다.
IP·브라우저 헤더·만료·원본 접근 제한 때문에 원본 경로는 실패할 수 있다. 원본 성공 시에만 봇의
음원 업로드를 줄이며, 원본 조회 CPU/메타데이터 트래픽까지 0인 것은 아니다.

### 파일 응답

`GET|HEAD /music/api/guilds/{guild_id}/stream/{item_id}`:
로그인·길드 멤버십/기존 승인 게이트 + **현재 또는 바로 다음 곡**인지 검사한다.
슬롯 대기 뒤에도 인가와 큐를 다시 검사하며, 요청으로 yt-dlp 다운로드를 시작하지 않는다.

`200`, 단일 Range의 `206`, 범위 밖의 `416`(`Content-Range: bytes */길이`),
`If-None-Match`의 `304`, `If-Range` 불일치 시 전체 `200`을 지원한다.
HEAD는 Range를 무시하고 전체 길이만 준다. 잘못된 형식/다중 Range는 Range를 무시하고 200이다.
MIME은 `audio/ogg; codecs=opus`, ETag는 실제 파일 SHA-256이다.
단일 206 본문은 최대 1 MiB다. 요청 범위가 더 크면 `Content-Range`의 끝 다음부터
클라이언트가 재요청한다. 전체 200/HEAD 및 If-Range 불일치 의미는 바꾸지 않는다.
이는 [RFC 9110 §15.3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7)의
요청 범위 일부 응답이다. 큰 파일의 SHA-256은 경로·크기·수정 시각별 최대 128개를
메모리에 보관하여 매 Range마다 전체 파일을 다시 읽지 않는다. 파일 수정 시 다시 계산한다.
`Cache-Control: private, no-cache`, `Vary: Cookie`로 인가 재검증과 공용 캐시 금지를 명시한다.
CORS를 열지 않는 동일 오리진 API이고, 서비스워커 `/music/api/*` 우회 경로를 쓴다.

로그인 없음은 401, 길드 접근 거부는 403, 허용 목록 밖/라이브/미지원 파일은 404다.
전역 꺼짐·캐시 미스·대기 시한은 503, 큐 또는 사용자 요청 상한은 429이며
429/503은 `Retry-After: 5`를 준다. 오류 응답은 저장하지 않는다.

전역 대기 포함 512건, 사용자별 최대 2건. 현재 곡 우선, 다음 곡은 종료 예정 시각 순이다.
미리받기는 동시 전송 상한이 2 이상이면 최소 1자리를 현재 곡에 남긴다.
대기는 최대 25초(다음 곡의 마감이 더 빠르면 그때), 전체 요청 수명은 180초다.
본문은 16 KiB 단위, 사용자당 고정 60초 창 64 MiB를 넘으면 연결을 끝낸다.
소비자가 읽지 않아도 시한이 지나면 파일 pin과 슬롯을 반납한다.

클라이언트는 최대 32 MiB 파일 두 개만 Blob으로 유지한다. 실패하면 설정된 다음 경로로
이동하며, 후보 교체·끄기·정책 변경·페이지 종료 때 요청을 취소하고 URL을 해제한다.
32 MiB 초과 파일은 같은 audio에 인증된 동일 오리진 URL을 연결한다. 브라우저가
Range로 필요한 부분을 받고 다음 곡도 `preload=auto`로 준비한다. 이는 힌트이며 MSE·remux는 없다.
전체 선다운로드나 오프라인 재생은 보장하지 않으며, 버퍼 밖으로 이동하면 네트워크가 필요하다.
라이브·코덱/디코딩 오류에는 기존 임베드로 폴백한다.
다운로드는 예산·동시성에 따라 180초 안에 끝나지 않을 수 있으며 이때 다음 경로로 이동한다.
원본 Blob은 30초, 원본 조회 클라이언트 대기는 17초, native 초기 준비/버퍼 정지는 20초 한도다.
서버 캐시가 없으면 최대 30초 기다린다. 모든 경로가 꺼졌거나 실패했고 embed도 없으면 무음과 안내다.
두 audio는 DOM에 계속 유지한다. 다음 곡은 서버가 실제로 바꾼 뒤에만 틀고,
진짜 무간격이나 JS 동결 상태의 곡 전환은 보장하지 않는다.

포털의 다운로드 현황은 서버 descriptor의 `ready`/`sizeBytes`와 기기의 수신 상태를
구분한다. Blob은 수신 바이트·남은 바이트·진행률·전송 평균 속도 기반 예상 시간을 표시한다.
전송 큐 대기 시간은 예측하지 않으며, Range는 정확한 받은 바이트 대신 현재 위치 이후
연속 `audio.buffered` 초를 표시한다. 탭 메모리 보관을 영구 저장이나 서버 캐시 목록으로 부르지 않는다.

### 검증

`cargo test --workspace`에 Range/인가/ETag/HEAD/캐시 pin/전역 속도·우선순위 테스트가 있다.
실제 브라우저 검증은 `scripts/Test-WebDirectStream.cjs`다. 로컬 개발 서버와
`playwright-core`, Chromium, 30초 이상 Opus 시험 파일이 필요하다.
`PLAN05_BASE`(기본 `http://127.0.0.1:8791`), `PLAN05_CHROME`, `PLAN05_AUDIO`로 지정한다.
실제 포털·오디오 디코더를 사용하고 곡 일정·외부 임베드·파일 응답은 고정 fixture로 대체한다.
장시간 Android 실기기/잠금/절전/블루투스 검증은 별도로 남는다. 배포는 이 작업에 포함하지 않는다.

Android 포털 검증은 `scripts/Test-AndroidWebDirectStream.cjs`다. 위 로컬 서버와
Play Store 이미지의 실행 중인 AVD(Chrome 설치), `playwright-core`가 필요하다.
`PLAN05_DEVICE`는 에뮬레이터 serial(기본 `emulator-5554`)만 받는다. 해당 AVD의 Chrome을
시험 사이에 종료하므로 개인 작업용 AVD에서는 실행하지 않는다. 운영 서버에는 접속하지 않는다.

```powershell
ffmpeg -y -loglevel error -f lavfi -i sine=frequency=440:duration=90 -c:a libopus -b:a 128k .devrun/plan05-avd-tone.opus
ffmpeg -y -loglevel error -f lavfi -i sine=frequency=440:duration=2100 -c:a libopus -b:a 128k .devrun/plan05-avd-long.opus
node scripts/Test-AndroidWebDirectStream.cjs
$env:PLAN05_RANGE = '1'
node scripts/Test-AndroidWebDirectStream.cjs
Remove-Item Env:PLAN05_RANGE
```

실제 portal/core와 Android Opus 디코더를 쓰며, 일정·외부 임베드·음원은 로컬 fixture다.
Range 시험은 32 MiB 초과의 실제 Opus를 1 MiB씩 응답한다. 홈 45초·화면 꺼짐 45초·
꺼진 화면에서 곡 경계 110초를 측정한다. CDP는 조작에만 쓰고 측정 전에 분리한다.
복귀 첫 visibility 이벤트의 미디어 시각과 Android `dumpsys audio`를 함께 검사하며,
실패 시 종료 코드 1이다. `.devrun/plan05-avd-{blob,range}*`에 보고와 스크린샷을 남긴다.
네트워크는 localhost/adb reverse이고 로그인도 개발 계정이다. 이 결과는 운영 OAuth·프록시·
실제 이동통신망·제조사 절전 정책·블루투스 검증을 대체하지 않는다.

### 봇 주인 설정 단일 진입점

`GET /music/owner`: Discord 봇 주인 전용, 길드 선택과 무관한 설정 화면이다. 서버별
`/music/guilds/{id}/admin#owner`에서는 이 페이지로 안내한다.
`GET /music/api/owner/playback`는 전역 재생 기본값·캐시/로그 한도·음성 정책만 반환한다.
`PUT`은 봇 주인 + CSRF가 필요하며 보낸 필드만 바꾼다. 숫자는 기존 범위로 제한하고
모르는 키·잘못된 타입은 400이다. 볼륨은 활성 길드에 즉시 반영한다.
호스트 쿠키 경로·브라우저 프로필·OAuth 비밀값은 이 API에 없고 변경도 거부한다.
기존 운영 `/settings`는 연결·도구 전용이며 CSRF 검증 후 해당 필드만 저장한다.
운영 사이트의 `/botsettings` 인증 설정과 Discord OAuth의 보안 경계는 합치지 않는다.
