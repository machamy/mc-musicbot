## 1. 권한별 지정 역할 (통짜 → 분리)

**문제**: `RemoteGuildSettings.configured_role_ids`가 하나뿐이라, 7개 권한 규칙이 전부 같은 역할 목록을 공유해요.
검색용으로 `@DJ`를 지정하면 볼륨·대기열편집에도 똑같이 먹어요. 사실상 "지정 역할" 옵션이 못 쓰는 상태예요.

**바꾸는 것**

```rust
pub struct RemoteGuildSettings {
    // 기존 필드 유지 — 마이그레이션 폴백용으로만 읽는다
    #[serde(default)]
    pub configured_role_ids: Vec<u64>,

    /// 규칙별 지정 역할. 키는 아래 7개 권한 키.
    #[serde(default)]
    pub rule_role_ids: BTreeMap<String, Vec<u64>>,
}
```

권한 키: `search` `vote` `chat` `playback` `seek` `volume` `queueEdit`

**마이그레이션**: `rule_role_ids`가 비어 있고 `configured_role_ids`가 비어 있지 않으면,
**읽는 시점에** 7개 키 전부에 기존 값을 복사해서 쓴다고 간주해요. 저장할 때 비로소 분리된 값이 기록돼요.
(기존 설정을 쓰던 서버의 동작이 조용히 바뀌면 안 되니까요.)

**관리자 판정(`is_manager`)** 은 별개예요. `rule_role_ids`가 아니라 **`manager_role_ids`** 라는
별도 필드를 새로 둬요. 지금은 `configured_role_ids`가 "권한용"과 "관리자 지정용"을 겸하고 있어서
검색 권한 역할을 준 사람이 관리자가 돼버려요. 이것도 같이 갈라요.

```rust
#[serde(default)]
pub manager_role_ids: Vec<u64>,
```
마이그레이션은 위와 같은 방식(비어 있으면 `configured_role_ids` 폴백).

**API 변경**

`GET /admin/settings` 응답:
```jsonc
{ "settings": {
  "ruleRoleIds": { "search": ["123"], "vote": [], "chat": [], "playback": [],
                   "seek": [], "volume": ["456"], "queueEdit": ["456"] },
  "managerRoleIds": ["789"]
  // configuredRoleIds 는 더 이상 보내지 않는다
}}
```
`PUT /admin/settings/perms` 도 같은 형태로 받아요. 전부 **문자열 배열**이에요(u64 정밀도).

`GET /admin/permission-preview?rule=configuredRole&key=volume&roleIds=1,2`
— `key`가 추가돼요. 어떤 권한의 미리보기인지 알아야 정확한 인원이 나와요.

`GET /state/cold`의 `permissions.entries[]`에 `roleNames: ["DJ"]`를 추가해요.
"내 권한" 화면에서 왜 되는지/안 되는지 설명할 때 역할 이름이 있어야 말이 돼요.

## 2. 개인 설정 서버 저장 (계정 저장)

**왜**: 화면 배치·테마 같은 걸 localStorage에만 두면 기기를 바꾸면 초기화돼요.
사용자가 "계정저장"을 명시적으로 요청했어요.

**새 테이블** (마이그레이션 v9)

```sql
CREATE TABLE remote_user_prefs (
  user_id INTEGER NOT NULL,
  key     TEXT    NOT NULL,
  value   TEXT    NOT NULL,
  updated_utc TEXT NOT NULL,
  PRIMARY KEY (user_id, key));
```

**길드가 아니라 유저 단위**예요. 화면 배치를 서버마다 다르게 쓰고 싶은 사람은 없어요.

**키 목록** (서버는 화이트리스트만 받아요 — 아무 키나 저장소로 쓰이면 안 되니까요)

| key | 값 | 기본 |
|---|---|---|
| `layout` | `three` \| `two` \| `panel` | 없음(=미선택) |
| `theme` | `dark` \| `light` | `dark` |
| `layoutSizes` | JSON 문자열, 최대 2KB | 없음 |
| `panelLayout` | JSON 문자열, 최대 8KB | 없음 |
| `lyricsOpen` | `1` \| `0` | `1` |

**API**

| 경로 | 내용 |
|---|---|
| `GET /music/api/prefs` | `{"prefs":{"layout":"two", ...}}` — 길드 무관, 세션만 있으면 돼요 |
| `PUT /music/api/prefs` | `{"layout":"two"}` 부분 갱신. 응답 `{"ok":true,"prefs":{…}}` |

`GET /state/cold` 응답에도 `"prefs": {…}`를 같이 실어요. 진입 시 왕복을 하나 줄이려고요.

**우선순위**: 서버 값 > localStorage > 기본값.
서버에서 받은 값은 localStorage에도 미러링해서 다음 첫 페인트가 안 튀게 해요.

## 3. 첫 진입 배치 선택창

`prefs.layout`이 **없으면**(한 번도 고른 적 없으면) 리모컨 첫 진입에 **배치 선택 시트**를 띄워요.

- 3개 카드: **3단** / **2단** / **패널**. 각각 미니 도식 + 한 줄 설명 + 짧은 부연.
- 고르면 즉시 적용 + `PUT /music/api/prefs`로 계정에 저장.
- **건너뛰기** 없어요. 대신 아무거나 고르면 되고, 나중에 프로필 드롭다운에서 언제든 바꿔요.
  (선택을 강요하는 대신, 셋 중 하나에 "가장 무난해요" 정도의 힌트를 줘요.)
- 두 번째 진입부터는 안 떠요.
- 시트 하단에 "나중에 프로필 메뉴에서 바꿀 수 있어요" 한 줄.

## 4. 접속·멤버 표시 정확도

지금 "듣는 중"이 봇과 **다른 음성 채널**에 있는 사람까지 잡고 있어요. 그러면 의미가 없어요.

**고칠 것**

- `listening` = **봇이 들어가 있는 그 음성 채널에 같이 있는 사람만**.
  봇이 음성 채널에 없으면 `listening`은 **항상 빈 배열**이에요.
- 봇이 다른 채널에 있는 사람은 `listening`이 아니라 별도로 표시해요:
  `inOtherVoice: ["userId", …]` — "다른 채널에 있어요"로 그려요.

**새로 내보낼 것** — `/state/hot`의 `presence`에 추가

```jsonc
"bot": {
  "inGuild": true,          // 봇이 이 서버에 들어와 있는지
  "inVoice": true,          // 봇이 음성 채널에 들어가 있는지
  "voiceChannelId": "123",
  "voiceChannelName": "일반",
  "listenerCount": 3        // 그 채널에 있는 사람 수(봇 제외)
}
```

**UI**
- 헤더 접속 요약: 봇이 음성에 없으면 `🎧듣는중 N` 대신 **`봇이 음성 채널에 없어요`** 로 바꿔요.
- 봇이 서버에 아예 없으면 그건 접속 요약이 아니라 **상단 배너**로 크게 알려요.
- 멤버 탭 그룹: `이 채널에서 듣는 중` / `다른 채널에 있어요` / `리모컨 보는 중` / `온라인` / `오프라인`.

## 5. 대기열 갱신 카운트다운

서버가 5초마다 재정렬해요. 지금은 순서가 갑자기 바뀌어서 왜 움직였는지 알 수가 없어요.

- 대기열 헤더의 모드 뱃지 옆에 **`갱신 5 4 3 2 1`** 카운트다운을 둬요. 간결하게, 숫자만 바뀌게.
- 기준 시각은 서버가 줘요. `/state/hot`과 `queue.set` 이벤트에 이미 `sortedAt`이 있으니,
  **`nextSortAt`** 을 추가로 실어 주면 클라이언트가 정확히 맞춰요.
  (클라 타이머만 쓰면 탭이 백그라운드에 갔다 오면 어긋나요.)
- 0이 되는 순간 재정렬 애니메이션(FLIP)이 돌면 인과가 눈에 보여요.
- 정렬 모드가 `fifo`면 순서가 안 바뀌니 카운트다운을 숨겨요. 의미 없는 숫자는 노이즈예요.

## 6. 브라우저에서 검색하기

**지금**: 봇 호스트에서 `yt-dlp`가 `ytsearch10:` 를 돌려요. 봇 PC가 느리거나 유튜브가 막으면 검색이 통째로 죽어요.

**추가**: YouTube Data API v3를 **브라우저에서 직접** 부르는 경로를 둬요. CORS가 열려 있어서 가능해요.

- 어드민(운영 패널 `/botsettings`)에 **YouTube API 키** 입력란을 둬요.
- 키가 설정돼 있으면 `/state/cold`에 `search: { mode: "browser", youtubeApiKey: "..." }` 로 내려줘요.
  키는 **HTTP 리퍼러 제한**을 걸어서 쓰는 전제예요. (그래도 공개되는 값이라는 걸 어드민 화면에 명시해요.)
- 키가 없으면 `search: { mode: "server" }` — 지금처럼 서버가 검색해요.
- 브라우저 검색이 실패하면(할당량 초과·네트워크) **조용히 서버 검색으로 폴백**하고,
  결과 위에 `서버에서 찾았어요` 같은 작은 표시를 남겨요.
- 브라우저 검색 결과도 `track` 형태로 정규화해야 해요:
  `{title, artist(channelTitle), provider:"YouTube", contentId(videoId), cacheKey, durationSeconds, artUrl}`
  YouTube Data API의 `search.list`는 길이를 안 줘요. `videos.list?part=contentDetails`로 한 번 더 불러
  ISO8601 duration을 초로 바꿔요. (두 번 부르는 게 싫으면 길이는 담은 뒤 서버가 채워도 돼요.)

## 7. 크기 조절 + 패널형 배치

### 7.1 크기 조절 (3단·2단 공통)

- 열 사이 경계에 **드래그 핸들**. 마우스로 끌면 너비가 바뀌어요.
- 채팅 열 안에서 목록/입력 사이도 세로로 조절돼요.
- 최소/최대 폭을 둬서 아무리 끌어도 화면이 안 깨지게 해요.
- 더블클릭하면 기본값으로 돌아가요.
- 값은 `prefs.layoutSizes`에 저장(계정). 예: `{"three":{"rail":320,"side":380},"two":{"side":390}}`
- 키보드로도 조절돼야 해요(핸들에 포커스 → 화살표). 접근성 기준이에요.

### 7.2 배치 6종

**절대 원칙 — 배치가 달라도 기능은 완전히 같아요.**

- DOM은 **한 벌**이에요. 배치는 CSS 그리드 배치와 "누가 스크롤하는가"만 바꿔요.
- 패널을 옮겨야 하면 **노드를 이동(`appendChild`)** 만 해요. **다시 만들지 마요.**
  새로 만들면 이벤트 핸들러와 `data-testid` 가 죽고, 배치마다 기능이 달라지는 사고가 나요.
- 어느 배치에서도 `data-testid` 24개가 전부 살아 있어야 해요.
- 배치 전용 기능을 만들지 마요. "패널형에서만 되는 것"이 생기는 순간 원칙이 깨져요.
- 새 기능을 추가할 때는 **모든 배치에서 확인**해요.

`<html data-layout="...">` 하나로 갈려요. 값은 아래 6개예요.

| 값 | 이름 | 누구를 위한 배치인가 | 구조 |
|---|---|---|---|
| `three` | **3단** (기본) | 대부분 | 좌 레일(검색·대기열·보관함) / 중앙 스테이지 / 우 탭 |
| `two` | **2단** | 넓은 재생 화면 + 채팅 고정 | 좌측 한 컬럼(스테이지→레일) / 우측 390px sticky |
| `focus` | **집중** | 음악만 틀어놓고 볼 때 | 스테이지가 화면을 거의 다 씀. 레일·사이드는 **가장자리 오버레이**로 열림 |
| `dj` | **DJ** | 곡을 계속 고르고 넣을 때 | 좌측 **넓은 대기열+검색**, 우측 위 컴팩트 재생 / 아래 채팅 |
| `talk` | **수다** | 채팅이 주인공 | 좌측 컴팩트 재생 바 + 대기열, 우측 **넓은 채팅** |
| `panel` | **패널** | 내 맘대로 | 도킹 트리. 아래 §7.3 |

**공통 규칙**
- 680px 이하에서는 **6종 전부** 단일 컬럼 + 하단 탭바로 폴백해요. 좁은 화면에서 배치 차이는 의미가 없어요.
- 각 배치는 §7.1 의 크기 조절을 지원해요. 조절값은 배치별로 따로 저장돼요
  (`prefs.layoutSizes` 안에 `{"three":{...},"dj":{...}}` 처럼).
- 배치 전환은 **새로고침 없이 즉시**. 전환 프레임 동안 트랜지션을 죽여 튐을 막아요.

### 7.3 패널형 (`panel`) — 토스증권·유니티 에디터 방식

- **패널 단위**: `now`(지금 재생) · `queue`(대기열) · `search`(검색) · `library`(보관함) ·
  `chat`(채팅) · `members`(멤버) · `recent`(최근) · `audit`(로그) · `lyrics`(가사)
  (`suggest` 는 §11에서 모달로 빠지므로 패널 목록에 없어요)
- **도킹 트리**: 좌우/상하 분할을 재귀적으로 갖는 구조. 각 리프는 **탭 그룹**이에요.
  ```jsonc
  { "type":"split", "dir":"row", "ratio":0.72, "a":
      { "type":"split", "dir":"col", "ratio":0.55,
        "a": {"type":"tabs","panels":["now"],"active":"now"},
        "b": {"type":"tabs","panels":["queue","search","library"],"active":"queue"} },
    "b": {"type":"tabs","panels":["chat","members"],"active":"chat"} }
  ```
- **조작**: 탭을 끌어 다른 그룹에 붙이기 / 가장자리에 떨어뜨려 분할 생성 / 분할선 드래그로 비율 조절 /
  탭 닫기 / 상단 "패널 추가" 메뉴에서 닫은 패널 다시 열기
- 드롭 대상은 **끌기 중에 반투명 하이라이트**로 미리 보여줘야 해요. 안 보이면 못 써요.
- `prefs.panelLayout` 에 저장(계정). **기본 프리셋 1개** + "기본으로 되돌리기" 버튼.
- 680px 이하에서는 패널형을 쓰지 않고 단일 컬럼으로 폴백해요.

### 7.4 배치 고르는 화면

프로필 드롭다운의 "화면 배치"와 §3의 첫 진입 시트에서 **6개를 한눈에** 보여줘요.

- 각 카드에 **실제 열 비율을 줄여 그린 미니 도식** + 이름 + 한 줄 설명.
- 6개가 한 줄에 다 들어가면 답답하니 **3×2 그리드**로.
- 지금 쓰는 것에 체크 표시. 마우스를 올리면 그 배치가 어떤 상황에 좋은지 한 줄 더 보여줘요.
- 첫 진입 시트에서는 `3단` 에 **"가장 무난해요"** 힌트를 달아요.

## 8. 자동 재생 시드곡

**지금**: 자동 BGM은 최근 재생 목록에서 알아서 후보를 뽑아요. 사용자가 개입할 방법이 없어요.

**바꾸는 것**: 시드곡을 **직접 1~10곡** 등록하고, 추천 알고리즘이 그 곡들을 기준으로 비슷한 장르를 가져와요.

### 8.1 데이터

새 테이블 (마이그레이션 v10)

```sql
CREATE TABLE remote_autoplay_seeds (
  guild_id    INTEGER NOT NULL,
  cache_key   TEXT    NOT NULL,
  track_json  TEXT    NOT NULL,
  sort_order  INTEGER NOT NULL,
  added_by_user_id INTEGER NOT NULL,
  added_utc   TEXT    NOT NULL,
  PRIMARY KEY (guild_id, cache_key));
CREATE INDEX idx_autoplay_seeds_order ON remote_autoplay_seeds(guild_id, sort_order);
```

상한 10곡. 11번째를 넣으려 하면 서버가 거부하고 "시드곡은 10곡까지 넣을 수 있어요"로 답해요.

### 8.2 추천 방식

`AutoplayEngine`이 시드곡이 있으면 그걸 먼저 써요.

1. 시드가 **1곡 이상** 있으면: 매번 시드 중 하나를 **라운드로빈**으로 골라
   그 곡의 라디오(`RD{videoId}`)에서 후보를 뽑아요. 곡마다 돌아가며 써야 한 곡 장르로 쏠리지 않아요.
2. 시드가 **없으면**: 지금처럼 최근 재생 기반으로 동작해요 (기존 동작 유지).
3. 이미 대기열·최근 재생에 있는 곡, 라이브 방송, 길이 초과 곡은 후보에서 빼요 (기존 필터 유지).

### 8.3 권한

`RemoteGuildSettings`에 규칙을 하나 더 둬요. 다른 7개와 같은 `PermissionRule` 타입이에요.

```rust
#[serde(default = "default_autoplay_seed_rule")]
pub autoplay_seed_rule: PermissionRule,   // 기본 Administrator
```

권한 키는 `autoplaySeed`. §1의 `rule_role_ids`에도 이 키가 들어가요.
관리 콘솔의 "권한" 섹션에 8번째 항목으로 나와요. 설명: "자동 재생이 참고할 기준 곡을 등록·삭제하는 동작이에요."

### 8.4 API

| 경로 | 내용 |
|---|---|
| `GET /music/api/guilds/{id}/autoplay/seeds` | `{"seeds":[{cacheKey,track,addedByDisplayName,addedUtc}],"max":10,"canEdit":true}` |
| `POST /music/api/guilds/{id}/autoplay/seeds` | `{track}` → 추가. 중복이면 400 |
| `POST /music/api/guilds/{id}/autoplay/seeds/remove` | `{cacheKey}` |
| `POST /music/api/guilds/{id}/autoplay/seeds/reorder` | `{cacheKeys:[...]}` |

WS 토픽 `autoplay` 로 변경을 알려요. 활동 로그에 `autoplay.seed.add` / `.remove` 로 남겨요.

### 8.5 UI

- **유저 UI**: 대기열 탭 안에 `📻 자동 재생 기준 곡` 접이식 섹션. 권한이 있으면 편집 가능하고,
  없으면 목록만 보여요. 대기열 항목과 검색 결과에 **`📻 기준으로 삼기`** 버튼을 달아요.
- **관리 콘솔**: "순서와 재생" 섹션에 시드곡 목록 + 드래그 정렬 + 삭제.
- 시드가 0개면 "기준 곡이 없어서 최근에 튼 곡을 참고해요" 라고 지금 동작을 설명해요.

## 9. 웹에서 듣기 (브라우저 재생)

**요구**: 지금은 Discord 음성 채널에서만 들려요. 웹에서도 듣고 싶은데
**서버 부담은 딱 지금 수준(디코봇 정도)** 이어야 하고, **온/오프 토글**이고,
**볼륨 설정은 웹과 Discord가 별개**예요.

### 9.1 방식 — 브라우저가 YouTube에서 직접 받아요

서버가 오디오를 중계하면 듣는 사람 수만큼 대역폭과 CPU가 늘어나요. 요구사항과 정면으로 어긋나요.
대신 **YouTube IFrame Player API**를 써요. 브라우저가 유튜브에서 직접 받아 재생해요.

**서버 추가 부담: 0.** 새 엔드포인트도, 스트리밍도, 트랜스코딩도 없어요.
서버는 이미 보내고 있는 `positionSeconds` + `sampledAtUtc` + `contentId`만 그대로 쓰면 돼요.

```
Discord 음성 ← ffmpeg ← 봇 호스트 ← YouTube      (지금 그대로)
브라우저     ←──────────────────── YouTube      (새로 추가, 서버 안 거침)
                 ↑
            위치·곡 정보만 서버에서 받아 맞춤
```

### 9.2 동작

- 헤더나 재생 컨트롤 옆에 **`🔊 웹에서 듣기`** 토글. 기본 **꺼짐**.
- 켜면 숨긴 iframe 플레이어가 현재 곡을 **봇의 재생 위치에 맞춰** 시작해요.
- 곡이 바뀌면 자동으로 따라가요. 일시정지/재개도 봇을 따라가요.
- **위치 재동기화**: 봇 위치와 2초 이상 벌어지면 조용히 `seekTo`. 매 프레임 맞추려 들면 소리가 튀어요.
- 탭을 닫거나 토글을 끄면 즉시 멈춰요.
- 브라우저 자동재생 정책 때문에 **토글을 누르는 행위 자체가 사용자 제스처**가 돼요. 그래서 토글 방식이 맞아요.

### 9.3 볼륨 분리

- **웹 볼륨**은 iframe 플레이어에만 적용돼요. 개인 설정(`prefs.webVolume`, 0~100, 기본 60)에 저장해요.
- **Discord 볼륨**은 지금처럼 서버 설정이고 모두에게 공유돼요.
- 두 슬라이더를 **눈에 띄게 구분**해요. 웹 볼륨은 `🎧 내 볼륨(나만)`, Discord 볼륨은 `🔊 서버 볼륨(모두)`.
  헷갈리면 "왜 볼륨을 줄였는데 다른 사람도 줄어들지?" 사고가 나요.
- 웹에서 듣기가 꺼져 있으면 웹 볼륨 슬라이더는 숨겨요.

### 9.4 한계와 폴백 (숨기지 말고 그대로 알려요)

- **임베드가 막힌 영상**은 웹에서 못 들어요. iframe이 `onError`(101/150)를 주면
  `이 곡은 웹에서 재생할 수 없어요. Discord로 들어 주세요.` 로 안내하고 토글은 켜진 채로 다음 곡을 기다려요.
- **SoundCloud** 트랙은 1차 범위 밖이에요. `provider != YouTube*`면 같은 안내를 띄워요.
- 위치 동기가 완벽할 수는 없어요(네트워크 지연·버퍼링). ±1초는 정상이에요.
- 웹 재생은 **듣기 전용**이에요. 웹 플레이어를 조작해도 봇에는 영향이 없고, 그 반대만 성립해요.
  플레이어 UI를 노출하지 않는 이유이기도 해요.

### 9.5 개인 설정 키 추가

§2의 화이트리스트에 두 개를 더해요.

| key | 값 | 기본 |
|---|---|---|
| `webPlayback` | `1` \| `0` | `0` (꺼짐) |
| `webVolume` | `0`~`100` | `60` |

## 10. 투표 점수 설정 + 붐따(대기열에서 내리기)

### 10.1 점수를 서버마다 정할 수 있게

지금은 좋아요 1점, 슈퍼 좋아요 2점이 코드에 박혀 있어요(`QueueScore::total_score`가 `*2`를 하드코딩).
서버마다 다르게 쓰고 싶을 수 있으니 설정으로 빼요.

```rust
#[serde(default = "default_like_points")]        pub like_points: i32,        // 1
#[serde(default = "default_dislike_points")]     pub dislike_points: i32,     // -1
#[serde(default = "default_super_like_points")]  pub super_like_points: i32,  // 2
#[serde(default = "default_wait_points")]        pub wait_points: i32,        // 1 (곡 하나 지날 때마다)
```

허용 범위는 `-10 ~ 10`. `total_score()`가 이 값들을 받아 계산하도록 시그니처를 바꿔요
(`QueueScore::total_score(&self, points: &VotePoints) -> i32`). **호출부가 여러 곳이니 전부 갱신해요.**

관리 콘솔 "순서와 재생"에 숫자 입력 4개 + **지금 대기열에 적용하면 어떻게 바뀌는지 미리보기**를 둬요.
유저 UI의 점수 계산식 표시(`👍3 + ⭐1×2 + 대기2 = 7`)도 설정값을 반영해야 해요. 안 그러면 화면이 거짓말을 해요.

### 10.2 싫어요 (새 투표 종류)

`QueueVoteKind`에 `Dislike`를 추가해요. 좋아요/슈퍼좋아요와 **상호 배타**예요(하나만 켜져요).
`/vote`의 `kind`에 `"dislike"`가 추가돼요. 본인 곡에는 못 눌러요(기존 규칙과 동일).

### 10.3 붐따 — 싫어요가 모이면 대기열에서 내려요

```rust
#[serde(default)]                          pub boomtta_enabled: bool,      // 기본 false
#[serde(default = "default_boomtta_threshold")] pub boomtta_threshold: u32, // 기본 3
#[serde(default)]                          pub boomtta_action: BoomttaAction, // 기본 Bottom

pub enum BoomttaAction { Bottom, Remove }   // 맨 뒤로 / 아예 빼기
```

- **꺼져 있으면(기본)** 싫어요는 점수에만 영향을 줘요. 곡이 사라지지 않아요.
- 켜면 한 곡의 싫어요 수가 `boomtta_threshold` 이상이 되는 순간 `boomtta_action`을 실행해요.
- **지금 재생 중인 곡에는 적용하지 않아요.** 대기열 곡만이에요. (재생 중 강제 스킵은 다른 기능이고,
  사용자가 고른 건 "대기열에서 내리기"예요.)
- 실행되면 활동 로그에 `queue.boomtta`로 남기고, 신청자에게 토스트로 알려요. 조용히 사라지면 사고예요.
- 관리 콘솔 "순서와 재생"에 토글 + 기준 수 + 동작(맨 뒤로/빼기)을 둬요.

### 10.4 점수 계산과 "누가 눌렀는지" 보여주기

대기열이 길어지면 "왜 저 곡이 나보다 앞이지?"가 궁금해져요. 그때 답을 줄 수 있어야 해요.

**누가 눌렀는지** — 데이터는 이미 있어요. `remote_queue_votes(item_id, user_id, kind)` 에 다 들어 있는데
지금은 **개수만 세고 누구인지는 안 내보내요.**

`/state/hot` 의 큐 항목 `score` 에 추가:

```jsonc
"score": {
  "waitScore": 2, "likeCount": 3, "superLikeCount": 1, "dislikeCount": 0,
  "manualPriority": null, "totalScore": 7,
  "likeBy":  ["101","102","103"],   // 최대 12개까지만
  "superBy": ["104"],
  "dislikeBy": []
}
```

- **이름이 아니라 ID를 보내요.** 클라이언트가 이미 갖고 있는 `members` 목록으로 이름을 붙여요.
  서버가 이름을 조회하면 쿼리가 늘어나요. 모르는 ID는 `누군가` 로 그려요.
- 항목당 **최대 12명**까지만. 그 이상이면 `likeCount` 로 `+5명` 처럼 보여줘요.
  대기열 50곡 × 투표자 전원을 실으면 payload 가 터져요.
- UI: 점수 칩에 마우스를 올리면 **누가 눌렀는지 아바타와 이름**이 툴팁으로 떠요
  (레퍼런스 v1.26.0 의 "누가 좋아요를 눌렀는지 보여요"와 같은 동작).
  지금 재생 중인 곡은 툴팁 말고 **카드에 바로** 보여줘요 — 제일 궁금한 곡이니까요.

**점수 계산식** — 지금도 `👍3 + ⭐1×2 + 대기2 = 7` 을 보여주고 있어요. 두 가지를 더해요.

1. §10.1 에서 점수가 설정값이 됐으니 **설정값을 반영**해야 해요.
   좋아요를 2점으로 바꿨는데 화면이 `👍3 + …` 를 1점으로 계산하면 거짓말이에요.
2. 대기열이 **5곡 이상**이면 헤더에 **`왜 이 순서인가요? ⓘ`** 를 띄워요.
   누르면 지금 모드의 규칙 + 동점 처리 순서 + 5초마다 다시 정렬된다는 설명을 시트로 보여줘요.
   4곡 이하일 땐 굳이 안 띄워요 — 눈으로 봐도 알거든요.

`fifo` 모드에서는 점수가 순서에 영향을 안 주니 계산식을 **회색으로 흐리게** 하고
`지금은 신청 순서대로 나가요` 를 덧붙여요. 점수가 보이는데 순서와 무관하면 그게 제일 헷갈려요.

## 11. 제안 게시판을 모달로

지금 제안이 우측 탭 하나를 차지하는데, 자주 쓰는 기능이 아니라 탭 자리가 아까워요.

- 우측 탭에서 **제거**하고, 헤더에 **`💡 제안`** 버튼을 둬요.
- 누르면 **모달**로 열려요. 목록 + 작성 + 👍공감 + 상태 칩이 전부 그 안에 들어가요.
- 새 제안이 올라오면 버튼에 작은 점을 찍어요(안 읽은 표시). 숫자까지는 필요 없어요.
- 관리자면 모달 안에서 바로 상태를 바꿀 수 있어요.
- 패널형 배치에서는 `suggest`를 **패널 목록에서 빼요.** 모달이니까요.

## 12. 개인 재생목록

**지금 있는 건 서버 재생목록이에요.** `PlaylistScope`가 `Global`/`Guild`뿐이라 개인 것은 아직 없어요.

### 12.1 데이터

`PlaylistScope`에 `User`를 추가해요. `playlists` 테이블에 `owner_user_id` 컬럼이 이미 있으니 스키마 변경은 없어요.
`scope='User'` + `owner_user_id=나` 로 저장해요. **길드에 묶이지 않아요** — 내 재생목록은 어느 서버에서든 보여요.

`db.rs`의 `list_playlists`가 `PlaylistScope::User`를 받으면 `owner_user_id`로 거르도록 바꿔요.
(레거시 테이블이라 컬럼 추가는 하지 않고 `scope` 값만 늘려요. C# 엔진은 이 값을 모르지만
`PlaylistScope::parse`가 모르는 값을 `Global`로 떨어뜨리지 않도록 주의해요.)

### 12.2 UI — 여기가 핵심이에요

보관함 탭을 `👍 좋아요 / 🔖 담아둔 곡 / 📃 내 재생목록 / 🌐 서버 재생목록` 4개 세그먼트로 만들어요.

- **만들기**: `+ 새 재생목록` 버튼 → 이름만 입력하면 끝. 모달 없이 인라인으로.
- **곡 담기**: 대기열·검색 결과·보관함 어디서든 `＋` 버튼 → **재생목록 선택 팝오버**.
  자주 쓴 순으로 정렬하고, 맨 위에 "새로 만들기"를 둬요.
- **꺼내기**: 재생목록 카드에서 `▶ 전부 담기` / 곡별 `＋ 담기`.
- **정리**: 곡 드래그로 순서 바꾸기, 곡 삭제, 이름 바꾸기, 재생목록 삭제(확인 시트).
- **개수 표시**: `12곡 · 48분` 처럼 총 길이까지 보여주면 고를 때 편해요.
- 서버 재생목록과 개인 재생목록을 **아이콘과 색으로 확실히 구분**해요. 실수로 서버 것을 지우면 곤란해요.

### 12.3 권한

**`재생목록 전체 담기`를 별도 권한으로 빼요.** 한 번에 수십 곡이 들어가서 대기열을 통째로 점거할 수 있어요.

```rust
#[serde(default = "default_playlist_enqueue_rule")]
pub playlist_enqueue_rule: PermissionRule,   // 기본 GuildMember
```
권한 키 `playlistEnqueue`. §1의 `rule_role_ids`에도 들어가요. 이제 권한이 **9개**예요.

- **개인 재생목록을 만들고 고치는 것은 권한 대상이 아니에요.** 내 것이니까요.
- **서버 재생목록을 고치는 것**은 기존 `queue_edit_rule`이 아니라 관리자 권한으로 옮겨요.
- 전체 담기는 `max_queue_per_user` 상한을 그대로 지켜요. 넘으면 넘는 만큼만 담고
  `대기열 한도까지 N곡만 담았어요` 라고 알려요. 조용히 자르면 안 돼요.

## 13. 활동 로그를 사람이 읽는 피드로

### 13.1 지금 뭐가 문제인가

두 가지가 겹쳐 있어요.

1. **읽을 수가 없어요.** `settings.update` 같은 기계용 액션명에 `before_value`/`after_value` JSON 덩어리가
   그대로 나와요. 사람이 볼 화면이 아니에요.
2. **정작 궁금한 게 기록이 안 돼요.** 실제로 `add_audit` 호출부가 5곳뿐이고 대부분 `settings.*` 예요.
   누가 곡을 담았는지, 누가 좋아요를 눌렀는지는 **아예 남지 않아요.**

### 13.2 나눠요 — 사람 피드 / 운영 로그

| | 유저 UI `로그` 탭 | 관리 콘솔 `활동 기록` | 운영 패널 `/logs` |
|---|---|---|---|
| 내용 | 사람이 한 일, 한 문장씩 | 사람 피드 + 설정 변경 전후값 + 실패 사유 | 프로세스 로그(기존 그대로) |
| 예 | `민수님이 곡을 담았어요` | `지훈님이 최대 볼륨을 200 → 150 으로 바꿨어요` + 원본 JSON | `[Bot] Registered 25 slash commands.` |
| 보는 사람 | 멤버 전부 | 서버 관리자 | 봇 주인 |

`remote_audit_logs` 테이블은 그대로 쓰되, **액션마다 "사람 문장"과 "분류"를 매핑**해요.
전후값 JSON은 유저 UI 응답에 **아예 싣지 않아요.** 관리 콘솔에만 내려요.

### 13.3 남겨야 하는 행동 (전부 새로 추가)

| action | 분류 | 문장 |
|---|---|---|
| `queue.add` | `song` | `{누구}님이 **{곡}** 을 담았어요` |
| `queue.remove` | `song` | `{누구}님이 **{곡}** 을 뺐어요` |
| `queue.pin` | `song` | `{누구}님이 **{곡}** 을 맨 앞으로 올렸어요` |
| `queue.boomtta` | `song` | `**{곡}** 이 싫어요 {N}개로 대기열에서 내려갔어요` |
| `playlist.enqueue` | `song` | `{누구}님이 재생목록 **{이름}** 에서 {N}곡을 담았어요` |
| `vote.like` | `vote` | `{누구}님이 **{곡}** 에 좋아요를 눌렀어요` |
| `vote.superlike` | `vote` | `{누구}님이 **{곡}** 에 슈퍼 좋아요를 눌렀어요` |
| `vote.dislike` | `vote` | `{누구}님이 **{곡}** 에 싫어요를 눌렀어요` |
| `playback.pause` / `.resume` / `.skip` / `.seek` | `playback` | `{누구}님이 일시정지했어요` 등 |
| `playback.volume` | `playback` | `{누구}님이 서버 볼륨을 {N}으로 바꿨어요` |
| `playlist.create` / `.rename` / `.delete` | `playlist` | `{누구}님이 재생목록 **{이름}** 을 만들었어요` |
| `autoplay.seed.add` / `.remove` | `playlist` | `{누구}님이 **{곡}** 을 자동 재생 기준 곡으로 등록했어요` |
| `chat.delete` | `moderation` | `{누구}님이 메시지를 지웠어요` |
| `user.suspend` / `.unsuspend` | `moderation` | `{누구}님이 {대상}님을 {범위} 정지했어요 ({기간})` |
| `settings.*` | `admin` | `{누구}님이 {항목} 을 {전} → {후} 로 바꿨어요` |

- **취소는 기록하지 않아요.** 좋아요를 눌렀다 뗐다 반복하면 피드가 도배돼요.
  같은 사람이 같은 곡에 **1분 안에 같은 종류**를 다시 하면 기존 줄을 갱신해요(합치기).
- 곡 제목은 40자에서 자르고 툴팁에 전체를 보여줘요.
- 문장은 전부 **~해요체**예요.

### 13.4 필터

칩 형태로 위에 붙여요. **복수 선택**이고, 선택은 `prefs.auditFilter`에 저장해요(계정).

`🎵 곡` `👍 투표` `▶ 재생` `📃 재생목록` `🛡 관리`

**기본값**: `곡` + `재생목록` **만 켜요.**
투표는 사람이 많으면 초당 여러 줄이 쌓여서 다른 게 안 보이고, 재생 조작과 관리는 평소엔 관심 밖이에요.
기본값이 조용해야 로그창이 쓸모 있어요. 필터를 끄면 몇 줄이 숨겨졌는지 `+ 12개 더` 로 알려줘요.

관리 콘솔 쪽은 기본으로 **전부 켜고**, 거기에 `실패만 보기` 토글을 하나 더 둬요.

### 13.5 API

- `GET .../audit?before=&kinds=song,playlist` — `kinds` 필터 추가.
  유저 UI 응답 항목: `{id, kind, actorName, actorId, text, trackTitle?, createdUtc, mergedCount?}`
  **`text`는 서버가 완성해서 내려요.** 클라이언트가 액션명을 문장으로 바꾸는 로직을 갖지 않게요.
- `GET /admin/audit?...` — 위에 더해 `beforeValue` `afterValue` `success` `failureReason` 포함.
- WS 토픽 `audit` 는 지금처럼 "탭이 열려 있을 때만 재조회" 로 두되, **payload에 새 항목 하나를 실어**
  열려 있는 로그 탭이 통째로 재조회하지 않고 한 줄만 덧붙이게 해요.

### 13.6 보존

지금 `audit_retention_days` 기본 14일이에요. 투표까지 남기면 양이 확 늘어나니
**분류별 보존 기간**을 둬요: `vote`·`playback` 은 3일, 나머지는 설정값 그대로.
`prune_all` 에서 같이 처리해요.

## 14. 다음 곡 미리 보여주기

### 14.1 둘 다 이미 계산돼 있어요 — 서버 부담 0

- **대기열 다음 곡**: `player.upcoming[0]`. 이미 `/state/hot` 의 `queue[0]` 으로 나가고 있어요.
- **다음 자동추천곡**: `GuildPlayerState.autoplay_preview: Option<QueueItem>` 에 **이미 들어 있어요.**
  곡이 시작될 때 `side_effects::resolve_preview` 가 미리 뽑아 두고, `prefetch_next` 가 파일까지 미리 받아 둬요.
  그런데 `web/remote.rs` 는 이 필드를 **한 번도 읽지 않아요.** 그냥 안 내보내고 있었을 뿐이에요.

즉 새 yt-dlp 호출도, 새 계산도 없어요. **JSON에 필드 하나 더 싣는 게 전부**예요.

### 14.2 API

`/state/hot` 에 추가:

```jsonc
"next": {
  "source": "queue" | "autoplay" | null,
  "item": { "id", "track": {…}, "requestedByDisplay", "requestedByUserId" } | null
}
```

- 대기열에 곡이 있으면 `source: "queue"`, `item` 은 `queue[0]` 과 같은 것.
- 대기열이 비었고 자동재생이 켜져 있으면 `source: "autoplay"`, `item` 은 `autoplay_preview`.
- 둘 다 없으면 `source: null`.

`playback` WS 이벤트에도 같이 실어요. 곡이 바뀌면 다음 곡도 같이 바뀌니까요.

### 14.3 UI

지금 재생 카드 **아래에 한 줄**로 붙여요. 카드를 하나 더 만들면 화면만 무거워져요.

```
┌──────────────────────────────────────────┐
│            [앨범아트]                     │
│  아이브 - I AM                            │
│  신청: 민수                               │
│  ▁▂▃▅▇▅▃▂▁                               │
│  ──────●────────────  2:14 / 4:02        │
│  ⏮  ⏯  ⏭   🔊────  🔁  🎲               │
├──────────────────────────────────────────┤
│ 다음  뉴진스 - Super Shy   ·  지훈        │   ← 대기열에서
└──────────────────────────────────────────┘
```

자동추천일 때는 라벨과 톤을 바꿔서 **"확정이 아님"** 을 드러내요.

```
│ 📻 다음 (자동)  aespa - Spicy             │
│    대기열이 비면 이 곡이 나와요            │
```

- 자동추천 줄은 조금 흐리게(`--text-3`) 그려서 대기열 곡과 구분해요.
- 자동추천 줄에 **`📻 이 곡 말고`** 버튼을 둬요. 누르면 그 후보를 제외하고 다시 뽑아요
  (레퍼런스 v1.21.0 의 🚫 와 같은 동작). 권한은 `autoplay_seed_rule` 을 따라요.
- 자동추천 줄에 **`＋ 대기열에 담기`** 도 둬요. 마음에 들면 확정시킬 수 있게요.
- 다음 곡이 없으면 그 줄을 통째로 숨겨요. `다음 곡 없음` 같은 빈 줄은 노이즈예요.
- 곡 제목이 길면 마퀴가 돌아요(행 호버).

### 14.4 주의

- 대기열은 **5초마다 재정렬**되니 "다음 곡"이 바뀔 수 있어요. 그게 정상이고, §5의 카운트다운과 같이 보면
  왜 바뀌었는지 이해돼요. 바뀔 때 짧게 하이라이트를 줘서 눈에 띄게 해요.
- 누가 곡을 담으면 자동추천 다음 곡은 밀려요. 그래서 자동추천 줄 문구가 "대기열이 비면"이에요.
  "다음에 이게 나와요"라고 단정하면 거짓말이 돼요.

## 15. 차트에서 곡 담기

### 15.1 어떻게 가져오나 — 이미 있는 걸 씁니다

`YtDlp::expand_collection(url, provider)` 가 이미 있어요. 재생목록 URL을 주면 곡 목록을 펼쳐 줘요.
**차트는 결국 "재생목록 URL"** 이므로 새 크롤러를 만들 필요가 없어요.

그래서 차트를 **URL 목록으로 정의**해요. 코드에 하드코딩하지 않고 데이터로 둬요 —
유튜브가 차트 재생목록 ID를 바꿔도 코드를 안 고치고 관리 콘솔에서 주소만 갈아 끼우면 돼요.

```sql
-- 마이그레이션 v11
CREATE TABLE remote_charts (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  guild_id    INTEGER,            -- NULL 이면 모든 서버 공용(기본 제공분)
  category    TEXT NOT NULL,      -- popular | region | genre | karaoke
  name        TEXT NOT NULL,      -- "한국 인기곡"
  provider    TEXT NOT NULL,      -- YouTubeMusic | YouTube | SoundCloud
  url         TEXT NOT NULL,
  sort_order  INTEGER NOT NULL,
  enabled     INTEGER NOT NULL DEFAULT 1);

CREATE TABLE remote_chart_cache (
  chart_id    INTEGER PRIMARY KEY,
  tracks_json TEXT NOT NULL,
  fetched_utc TEXT NOT NULL);
```

**캐시가 핵심이에요.** 차트 하나 펼치는 데 yt-dlp 가 몇 초씩 걸려요.
`fetched_utc` 가 **6시간** 안이면 캐시를 그대로 줘요. 여러 사람이 같은 차트를 눌러도 yt-dlp 는 한 번만 돌아요.
동시에 같은 차트를 요청하면 **하나만 실행하고 나머지는 그 결과를 기다려요**
(`resolve_preview` 의 `try_begin_preview_resolve` 와 같은 방식). 안 그러면 yt-dlp 가 줄줄이 서요.

### 15.2 기본 제공 차트

`guild_id IS NULL` 로 기본 세트를 심어요(마이그레이션에서 1회).

| 분류 | 차트 |
|---|---|
| `popular` | 전세계 인기 · 한국 인기 · 오늘 뜨는 곡 |
| `region` | 미국 · 일본 · 영국 |
| `genre` | K-Pop · J-Pop · 힙합 · R&B · 록 · 일렉트로닉 |
| `karaoke` | TJ 인기차트 · TJ 발라드 · TJ 댄스 · 금영 인기차트 |
| `soundcloud` | SoundCloud 인기 (한국/전세계) |

**노래방 차트는 공식 유튜브 재생목록을 씁니다.** TJ미디어·금영 홈페이지를 긁으면
곡 제목만 나와서 **곡마다 유튜브 검색을 한 번씩 더** 해야 해요. 100곡이면 yt-dlp 100번이에요.
"서버 부담 최소" 원칙과 정면으로 어긋나서 안 해요. 공식 채널 재생목록이면 `expand_collection` 한 번으로 끝나요.

**작동하지 않는 차트가 생기면 숨기지 말고 그대로 알려요.** 관리 콘솔의 차트 목록에
`마지막 갱신 실패 · 2시간 전` 을 표시하고, 유저 UI 에서는 그 차트를 목록에서 빼요.
빈 차트를 눌렀는데 아무 일도 안 일어나는 게 제일 나빠요.

### 15.3 UI — 2단계로 들어가요

**"너무 다다다닥"을 피하는 게 이 화면의 요구사항이에요.** 차트를 20개 나열하면 그게 바로 다다다닥이에요.

좌측 레일의 `검색` 탭 옆에 **`📈 차트`** 탭을 추가해요. (탭이 4개가 되니 아이콘+짧은 라벨로.)

**1단계 — 분류 카드 5장**

```
┌─────────────┬─────────────┐
│ 🔥 인기      │ 🌏 나라별    │
│ 지금 많이    │ 미국·일본·   │
│ 듣는 곡      │ 영국         │
├─────────────┼─────────────┤
│ 🎸 장르      │ 🎤 노래방    │
│ K-Pop·힙합·  │ TJ·금영      │
│ 록·R&B       │ 장르별       │
├─────────────┴─────────────┤
│ ☁ SoundCloud               │
└───────────────────────────┘
```

**2단계 — 그 분류의 차트 목록**, 그리고 차트를 고르면 곡 목록.
뒤로 가기(`←`)로 한 단계씩 올라와요. 브라우저 뒤로가기도 먹게 해요.

**곡 목록 화면**
- 상단에 차트 이름 + `마지막 갱신 12분 전` + `↻ 새로고침`(관리자만, 캐시 무시)
- 곡마다 순위 뱃지 · 제목(마퀴) · 아티스트 · `＋ 담기` · `📻 기준으로 삼기`
- 상단에 **`전부 담기 (50곡)`** — 권한이 없으면 버튼을 숨기지 말고 **비활성 + 이유 툴팁**
- 이미 대기열에 있는 곡은 `＋` 대신 `담김` 회색 뱃지 (중복 방지)
- 처음 여는 차트는 스켈레톤을 보여줘요. yt-dlp 가 도는 몇 초 동안 빈 화면이면 고장으로 보여요.

### 15.4 권한 — `bulkEnqueue` 하나로 묶어요

§12에서 `playlistEnqueue` 를 만들기로 했는데, **차트 전부 담기도 같은 위험**이에요
(한 번에 수십 곡이 들어가 대기열을 점거). 권한을 두 개로 쪼개면 관리 화면만 복잡해져요.

```rust
#[serde(default = "default_bulk_enqueue_rule")]
pub bulk_enqueue_rule: PermissionRule,   // 기본 GuildMember
```

권한 키 `bulkEnqueue`. **재생목록 전체 담기 + 차트 전체 담기**를 함께 관장해요.
§12의 `playlistEnqueue` 는 이 이름으로 대체해요. 권한은 총 **10개**예요.

곡을 하나씩 담는 건 기존 `search_rule` 그대로예요. 한 번에 담는 것만 이 권한을 봐요.
`max_queue_per_user` 상한도 그대로 지키고, 넘으면 넘는 만큼만 담고
`대기열 한도까지 N곡만 담았어요` 라고 알려요.

### 15.5 API

| 경로 | 내용 |
|---|---|
| `GET .../charts` | `{"categories":[{key,label,icon,charts:[{id,name,provider,lastFetchedUtc,ok}]}]}` |
| `GET .../charts/{id}` | `{"chart":{id,name},"tracks":[track],"fetchedUtc","stale":false}` |
| `POST .../charts/{id}/enqueue` | `{}` → 전부 담기. `bulkEnqueue` 권한. `{ok,added,skipped,limited}` |
| `POST .../charts/{id}/refresh` | 관리자만. 캐시 무시하고 다시 가져와요 |

관리 콘솔 "순서와 재생" 아래에 **차트 관리** 섹션: 목록·켜기/끄기·순서·주소 수정·차트 추가.
기본 제공분은 지울 수 없고 끄기만 돼요. 되돌릴 수 없는 삭제는 위험해요.

활동 로그: `chart.enqueue` → `{누구}님이 차트 **{이름}** 에서 {N}곡을 담았어요` (분류 `song`).

## 16. 확인된 버그 — 이번에 반드시 고쳐요

사용자가 직접 겪은 것들이에요. 기능 추가보다 우선순위가 높아요.

### B1. 봇이 음성채널에 없는데 있다고 나와요 ⭐ 최우선

**증상**: 봇이 음성 채널에 안 들어가 있는데 리모컨은 들어가 있다고 표시해요.

**원인**: `player.voice_channel_id` 는 `guild_states` **테이블에 저장된 값**이에요.
봇이 정상 경로로 나가지 않으면(재시작·네트워크 끊김·Discord 가 끊음) 그 값이 그대로 남아요.
`coordinator.rs:236` 주석은 "songbird 의 라이브 연결이 권위 소스"라고 정확히 적어 뒀는데,
**웹만 저장값을 읽고 있었어요.**

`src/web/remote.rs` 의 `bot_voice_status` 에 같은 함정이 다시 들어갔어요:

```rust
let channel_id = guild.voice_states.get(&bot_id)
    .and_then(|voice| voice.channel_id)
    .map(|channel| channel.get())
    .or(player_channel);          // ← 캐시가 맞게 None 을 줘도 stale 값으로 덮어쓴다
```

**고칠 것**: `.or(player_channel)` 를 **제거**해요. Discord 캐시의 `voice_states` 가 진실이에요.
`GUILD_VOICE_STATES` 인텐트는 켜져 있어요. 캐시에 길드가 아직 없는 기동 직후 몇 초는
`in_guild: false` 가 이미 처리해요 — 잠깐 "확인 중"이 없는 걸 있다고 하는 것보다 나아요.

같은 이유로 아래도 전부 `bot_voice_status` 결과를 쓰도록 바꿔요:
`voiceChannelId`(3곳) · `voiceConnected` · `same_voice_channel` 판정.
**저장된 `player.voice_channel_id` 를 "지금 어디 있나"의 근거로 쓰는 곳이 하나도 남으면 안 돼요.**
그 값은 "다음에 어디로 들어갈까"에만 써요.

회귀 테스트를 붙여요: 캐시에 봇 voice_state 가 없고 저장값만 있는 상태 → `inVoice == false`.

### B2. 내 메시지에 이모지·답장을 못 달아요

코드상으로는 `.msg__tools` 가 `mine` 여부와 무관하게 붙어요(`portal.js` 의 `updateMessage`).
그런데 실제로 안 된다고 하니 **실제 화면에서 재현부터 하고** 고쳐요. 의심 가는 것:

- `.msg__tools { position: absolute; top: -12px }` 인데 `.msg` 에 `position: relative` 가 있는지 확인.
  없으면 엉뚱한 조상 기준으로 떠서 채팅 목록 밖으로 잘려요.
- 목록 **맨 위 메시지**는 `top: -12px` 가 스크롤 컨테이너 밖으로 나가 `overflow` 에 잘려요.
  첫 메시지는 툴바를 아래쪽(`top: auto; bottom: -12px`)에 띄우거나, 컨테이너에 여유 패딩을 줘요.
- 자기 메시지가 오른쪽 정렬이면 `right: var(--sp-2)` 가 화면 밖일 수 있어요.

**자기 메시지에 반응·답장을 막는 규칙은 넣지 마요.** 서버에도 그런 제한이 없어요
(자기 곡 투표 금지·자기 메시지 신고 금지만 있어요). 채팅 반응은 점수가 아니라 표현이라 막을 이유가 없어요.

### B3. 알림을 켤 수만 있고 끌 수가 없어요

지금 프로필 메뉴에 `🔔 알림 허용` 하나뿐이에요. 누르면 브라우저 권한을 요청하고 끝이에요.
한 번 켜면 앱에서 끄는 방법이 없어요.

**고칠 것**: 앱 자체의 on/off 스위치를 둬요. 브라우저 권한과 별개예요
(브라우저 권한은 JS 로 철회할 수 없으니, 앱이 자기 스위치를 갖는 게 맞아요).

- 프로필 메뉴 `🔔 알림` 을 **토글**로. 상태에 따라 문구가 바뀌어요.
  - 권한 없음 → `알림 켜기` (누르면 권한 요청)
  - 권한 있음 + 켜짐 → `알림 켜짐` + 스위치 ON
  - 권한 있음 + 꺼짐 → `알림 꺼짐` + 스위치 OFF
  - 브라우저가 거부함 → 비활성 + `브라우저 설정에서 알림이 막혀 있어요` 툴팁
- 종류별로 나눠요: `내 신청곡이 시작될 때` / `나를 부를 때(@멘션)` / `내 메시지에 답장이 올 때`
- `prefs.notify` 에 저장(계정). 예: `{"song":1,"mention":1,"reply":1}`
  §2의 개인 설정 화이트리스트에 `notify` 를 추가해요.
- 꺼져 있으면 브라우저 알림도, 탭 제목 숫자도 안 띄워요.

## 17. 테마 여러 종류 (코딩 에디터처럼)

지금은 다크/라이트 둘뿐이에요. `tokens.css` 가 애초에 토큰 오버라이드 구조라
**테마를 늘리는 건 싸요** — `[data-theme="X"]` 블록에서 같은 토큰 이름만 다시 정의하면 돼요.
CSS 도, JS 도, 레이아웃도 손 안 대요.

### 17.1 테마 7종

| 값 | 이름 | 결 | 느낌 |
|---|---|---|---|
| `dark` | **다크** (기본) | 남보라 강조, 거의 검정 배경 | 지금 것 |
| `light` | **라이트** | 흰 배경 | 지금 것 |
| `midnight` | **미드나잇** | 짙은 곤색 + 하늘색 강조 | Tokyo Night / One Dark 계열 |
| `slate` | **그레이** | 중성 회색, 채도 낮음 | GitHub Dimmed 계열. 눈이 제일 안 피곤해요 |
| `sepia` | **베이지** | 따뜻한 종이색 + 갈색 글씨 | Solarized Light 계열. 밝은 방에서 좋아요 |
| `retro` | **레트로** | 거의 검정 + 앰버 단색 | 옛날 CRT 터미널. 아마 제일 재밌고 제일 안 쓰일 거예요 |
| `nord` | **노르드** | 차가운 청회색 | Nord 팔레트 |

각 테마는 `tokens.css` 의 **모든 토큰을 빠짐없이** 정의해요. 하나라도 빠지면 다크 값이 새어 나와서
글씨가 안 보이는 조합이 생겨요. 특히 잊기 쉬운 것: `--presence-*`, `--tier-*`, `--shadow-*`,
`--art-wash`, `--focus-ring`.

`color-scheme` 도 테마마다 맞춰요 (`sepia`/`light` 는 `light`, 나머지는 `dark`).
안 맞추면 스크롤바와 폼 기본 위젯만 반대 색으로 튀어요.

### 17.2 대비 기준은 타협 안 해요

테마가 예뻐도 안 읽히면 실패예요. **모든 테마에서** 본문 대비 4.5:1, 큰 글씨 3:1 이상을 지켜요.
특히 `retro` 의 단색 팔레트와 `sepia` 의 저채도 조합에서 깨지기 쉬워요.
`--text-3`(보조 텍스트)와 `--text-4`(비활성)가 배경 대비 기준을 넘는지 테마마다 확인해요.

### 17.3 고르는 UI

지금 헤더의 🌓 토글 버튼을 **테마 메뉴**로 바꿔요.

- 누르면 7개가 **색 미리보기 스와치**와 함께 떠요. 이름만 있으면 뭐가 뭔지 몰라요.
  스와치는 그 테마의 `--surface-1` / `--accent` / `--text-1` 세 색을 나란히 보여주면 충분해요.
- 맨 위에 **`시스템 설정 따라가기`** 항목을 둬요 (`prefs.theme = "auto"`).
  고르면 OS 가 밝으면 `light`, 어두우면 `dark` 로 따라가요.
- 마우스를 올리면 **바로 미리보기**로 적용되고, 메뉴를 닫으면 확정돼요. 고르기 전에 보는 게 제일 확실해요.
  확정 안 하고 나가면 원래 테마로 되돌려요.
- 선택은 `prefs.theme` 에 저장(계정) + localStorage 미러링.

### 17.4 값이 늘어남에 따라 고칠 것

- `prefs.theme` 화이트리스트(§2)를 `auto|dark|light|midnight|slate|sepia|retro|nord` 로 넓혀요.
- `remote_page.rs` 의 FOUC 방지 인라인 스크립트는 **저장값을 그대로 `data-theme` 에 넣으므로
  코드 변경이 필요 없어요.** 다만 `auto` 는 값이 아니라 규칙이라 그 스크립트에서 풀어 줘야 해요:
  ```js
  var t=localStorage.getItem('macham.theme')||'dark';
  if(t==='auto')t=matchMedia('(prefers-color-scheme: light)').matches?'light':'dark';
  document.documentElement.dataset.theme=t;
  ```
- `<meta name="theme-color">` 도 테마에 맞춰 런타임에 갱신해요. 모바일 주소창 색이 안 맞으면 어색해요.
- 관리 콘솔(`console.css`)도 같은 토큰을 쓰니 **자동으로 따라와요.** 별도 작업 없어요.
  다만 콘솔에서도 테마가 적용되는지 눈으로 확인해요.

## 18. 대기열 상한 올리기 (그리고 그게 버티게 만들기)

### 18.1 지금 상한

| 항목 | 기본값 | 설정 가능 최대 |
|---|---|---|
| 1인 대기열 수 | 5곡 | **100곡** |
| 서버 대기열 수 | 100곡 | **1000곡** |

둘 다 너무 낮아요. 새 상한:

| 항목 | 기본값 | 새 최대 |
|---|---|---|
| 1인 대기열 수 | 5곡 (유지) | **1000곡** |
| 서버 대기열 수 | 100곡 (유지) | **10000곡** |

기본값은 안 건드려요. 기본이 갑자기 커지면 기존 서버의 "골고루 돌아가는" 동작이 조용히 바뀌어요.

### 18.2 숫자만 올리면 터지는 곳들 — 같이 고쳐요

상한은 `console.js` 의 `NUM_SPECS` 한 줄이에요. 문제는 **그 크기가 실제로 흘러가는 경로**예요.

**(1) WS payload** — `queue.set` 이벤트가 대기열 **전체**를 매번 실어요.
5000곡이면 프레임 하나가 수 MB 예요. 5초마다 재정렬될 때마다 접속자 전원에게 그게 나가요.
→ `queue.set` 과 `/state/hot` 은 **앞에서 200곡까지만** 보내고 `queueTotal` 로 전체 수를 알려요.
```jsonc
"queue": [ …최대 200개… ],
"queueTotal": 4820,
"queueTruncated": true
```
→ `GET .../queue?offset=200&limit=200` 으로 더 불러와요. 보통 사람은 앞 20곡만 보므로
평소에는 추가 요청이 아예 안 일어나요.

**(2) DOM** — 5000개 노드를 그리면 브라우저가 죽어요.
→ 대기열 목록에 **가상 스크롤**을 넣어요. 보이는 만큼만 노드를 만들어요.
FLIP 애니메이션은 **화면에 보이는 항목에만** 적용해요.

**(3) 정렬** — 5초마다 전체를 정렬해요. 5000개면 매번 O(n log n) + 점수 조회예요.
→ `resort_if_changed` 가 이미 "순서가 실제로 바뀐 길드만 저장"하니 쓰기는 괜찮아요.
읽기 쪽은 `queue_scores` 가 길드 전체를 한 번에 가져오므로 쿼리 수는 안 늘어요.
다만 **500곡을 넘으면 재정렬 주기를 5초 → 15초로 늘려요.** 그 정도 길이면 순서가 급하지 않아요.
화면의 카운트다운(§5)도 그 값을 따라가야 해요 — `nextSortAt` 을 서버가 주니 자동으로 맞아요.

**(4) 전부 담기** — §15.4 의 `bulkEnqueue` 로 차트 100곡, 재생목록 500곡이 한 번에 들어와요.
→ 지금처럼 `max_queue_per_user` 를 넘으면 넘는 만큼만 담고 몇 곡만 담겼는지 알려요.
→ 한 번에 담는 양 자체에 **별도 상한 200곡**을 둬요. 한 번의 클릭이 대기열을 5000곡으로 만들면
   되돌리기가 너무 어려워요.

**(5) 대기열 비우기** — 5000곡이 쌓였을 때 되돌릴 방법이 있어야 해요.
관리 콘솔에 **`대기열 비우기`** 를 두고, 유저 UI 대기열 헤더에도 관리자에게만 보여요.
확인 시트에 몇 곡이 지워지는지 숫자를 박아요.

### 18.3 안내 문구

숫자를 크게 열어 주되, 화면에서 결과를 알려줘야 해요.

- 슬라이더 옆에 값에 따라 힌트가 바뀌어요:
  - `~50곡`: `골고루 돌아가요`
  - `~200곡`: `넉넉해요`
  - `200곡 초과`: `한 사람이 대기열을 오래 차지할 수 있어요`
- 서버 대기열이 **500곡을 넘으면** 대기열 헤더에 `4820곡 · 정렬은 15초마다` 를 표시해요.
  왜 갑자기 느려졌는지 알 수 있게요.

## 19. 서버 블랙리스트를 관리 콘솔에서

지금 블랙리스트는 **운영 패널(`/blacklist`)에만** 있어요. 봇 주인만 볼 수 있죠.
그런데 "우리 서버에서 이 곡 좀 그만" 은 **서버 관리자가 판단할 일**이에요.

### 19.1 범위 — 자기 서버 것만 만져요

`BlacklistEntry.guild_id` 는 **`0` 이 전역**이에요 (`models.rs:421`).

- 서버 관리자는 **자기 길드 항목만** 추가·수정·삭제할 수 있어요.
- **전역 항목은 목록에 보이되 읽기 전용**이고 `봇 전체 규칙` 뱃지를 달아요.
  왜 막혔는지 모르는 게 제일 답답하니 보여는 줘요. 다만 못 지워요.
- 서버 관리자가 전역 항목을 지우거나 다른 길드 항목을 건드리려 하면 **서버가 403** 으로 막아요.
  UI 에서 숨기는 것에 의존하지 않아요.

### 19.2 API

전부 `/music/api/guilds/{id}/admin/blacklist`, Manager 이상.

| 경로 | 내용 |
|---|---|
| `GET /admin/blacklist` | `{"items":[{id,kind,pattern,note,createdUtc,createdByName,scope:"guild"\|"global"}]}` |
| `POST /admin/blacklist` | `{kind,pattern,note}` → 이 길드 항목으로 추가 |
| `POST /admin/blacklist/remove` | `{id}` — **전역 항목이면 403** |
| `POST /admin/blacklist/test` | `{query}` → 지금 규칙으로 막히는지 시험. `{blocked:bool, rule?}` |

활동 로그: `blacklist.add` / `.remove` (분류 `moderation`)
→ `{누구}님이 **{패턴}** 을 차단 목록에 넣었어요`

### 19.3 UI — 관리 콘솔 "채팅과 제안" 옆에 `차단 목록` 섹션

- 종류별 탭: `제목` / `채널·아티스트` / `링크`  (`BlacklistKind` 에 맞춰요)
- 각 항목: 패턴 · 메모 · 등록자 · 등록일 · 삭제. 전역 항목은 흐리게 + 자물쇠 아이콘
- 상단에 **시험 입력창**: 곡 제목이나 URL 을 넣으면 지금 규칙으로 막히는지 즉시 알려줘요.
  어떤 규칙에 걸렸는지도 같이요. 규칙을 넣고 나서 왜 안 막히는지 모르는 상황을 막아요.
- 추가는 인라인 폼으로. 모달까지 갈 일이 아니에요.
- 대기열 항목과 검색 결과의 `⋯` 메뉴에 **`차단 목록에 넣기`** 를 달아요.
  관리자가 실제로 차단하고 싶어지는 순간은 그 곡을 보고 있을 때예요.
  누르면 패턴이 채워진 채로 확인 시트가 떠요 (제목 그대로 넣을지, 채널 단위로 넣을지 고를 수 있게).

## 20. 공통 주의

- `data-testid` 24개는 **모든 배치에서** 살아 있어야 해요.
- 새 기능이 실패해도 리모컨 기본 동작(재생·대기열·채팅)은 살아 있어야 해요.

  (드래그 끝난 뒤 한 번, 300ms 디바운스).
